# 분석·안·버전 관리와 결론 동영상(컷) 설계

작성 2026-10-23. 근거: 사용자와의 대화(2026-10-22~23), `docs/autoview-guide.md`(이 PC 실험 포함), 컷 편집 화면 시안(https://claude.ai/artifact/PWyTLkNxAbByK7WKiXwJgP).

## 1. 왜 만드는가

ASH 시뮬레이션 결과는 경영진·의사결정권자에게 보고된다. 보고의 목적은 둘이다.

- **안 비교**: A/B/C 여러 컨셉 중 하나를 고르게 한다. 컨셉마다 장단점을 보여 준다.
- **개선 효과**: 리스크를 찾아 동선·운영안을 바꿨더니 수치가 이만큼 좋아졌다(AGV 대수 → 투자비 절감, 통로 부하율 등)를 보여 준다.

설득의 중심은 정량 효과이고, 동영상은 그 숫자가 왜 나왔는지 눈으로 납득시키는 장치다. 따라서 영상은 **같은 구역·같은 시각을 안마다 똑같이** 찍어 공정하게 비교할 수 있어야 하고, 리스크 장면(공급 0회, 지연 급증, 병목)을 쉽게 찾아 넣을 수 있어야 한다.

이번 범위는 두 부분이다.

1. **분석·안·버전 관리**: 결과를 "어느 의사결정의 어느 안의 몇 번째 버전"으로 묶는다. 컷 영상과 나중의 보고서가 이 구조 위에서 동작한다.
2. **결론 동영상(컷)**: 웹에서 DXF 도면 위에 구역을 잡아 컷 리스트를 만들고, 서버가 AutoView로 촬영해 MP4로 내보낸다.

안 비교 보고서(PPT 양식)는 **이번 범위가 아니다**. 영상이 나온 뒤 따로 설계한다. 다만 컷과 선정 정보가 나중에 보고서에서 그대로 쓰이도록 저장해 둔다.

## 2. 목표 / 비목표 / 실패로 볼 것

목표
- 분석 → 안 → 버전 구조로 작업을 묶고, 최종 보고용 버전을 고른다.
- ZWCAD에서 보낼 때 서버의 분석·안 목록을 받아 고른다.
- 웹 컷 편집기: DXF + AGV 경로 위에 사각형 구역, 컷 추가/수정/삭제/순서, 기울기·방향·원근, 배속.
- 결과에서 문제·병목·지연 장면을 찾아 컷 후보로 제시한다.
- 서버가 무인으로 컷마다 MP4를 만들고, 원하면 이어 붙인 1개도 만든다. 자막(컷 이름·시각·핵심 수치)을 입힌다.
- 같은 컷 리스트를 분석 안의 여러 선정 버전에 똑같이 적용한다.
- 휴대폰 브라우저에서도 결과 영상이 재생된다.

비목표
- 안 비교 보고서(PPT) 자동 생성 — 다음 작업.
- 차량·용기를 따라가는 카메라(사용자가 불필요하다고 확인. AutoView에서 동작하지도 않음).
- AVI 출력(AutoView에서 압축 창이 뜨고 빈 화면이 나옴). MP4만.
- 실시간 3D 미리보기 엔진. 편집기의 기울기 미리보기는 2D 도면을 기울여 보여 주는 근사로 충분하다.

실패로 볼 것
- 같은 컷이 안마다 다른 구역·시각으로 찍혀 비교가 불공정해지는 것.
- 영상 배속·길이가 입력과 다르게 나오는 것(가이드: 매뉴얼 공식대로 하면 2배 느려짐).
- 휴대폰이나 PPT에서 영상이 안 열리는 것.
- 촬영이 대화상자에 걸려 서버 작업 큐 전체가 멈추는 것.

## 3. 사용자가 정한 것

- 분석·안을 웹에 리스트로 두고, ZWCAD에서 보낼 때 서버의 목록을 받아 고른다.
- 같은 안도 v1, v2처럼 버전이 생긴다. 마지막에 몇 개를 골라 최종 보고에서 의사결정을 받는다.
- 컷 편집 화면은 **업로드된 DXF 기준**으로 구성하고, **최종 영상에도 DXF가 배경으로 나온다**.
- 구역은 사각형으로 지정, 파라미터를 넣어 리스트에 추가/수정/삭제.
- 컷 종류
  - 구역 고정: 일정 시간 촬영(기간·배속).
  - A → B 이동: A에서 N초, 이동 M초, B에서 L초, 배속. 차량·경로와 무관하게 지점에서 지점으로 카메라가 이동한다. 사각형을 작게 잡으면 클로즈업 이동.
  - 전체 영상, 병목 구간, 문제 구간(공급 0회, 특정 시점에 평균보다 크게 지연된 부분 등).
- 뷰 기울이기: 수치 입력 또는 마우스 휠로 임의 기울이기. 원근 끄기 옵션.
- 리스트에서 여러 개를 골라 영상을 내보낸다.
- 웹 화면 기준(PC)으로 배치가 잘 맞아야 한다. 휴대폰에서도 볼 수 있어야 한다.
- 서버에 AutoView 라이선스가 있다.

## 4. 분석·안·버전

### 4.1 구조

- **분석**: 이름(예: "P동 1층 AGV 대수 검토"), 메모, 만든 날짜.
- **안**: 분석 안의 이름(A안, B안, …), 메모.
- **버전**: 안에 속한 작업 하나. 보낼 때마다 서버가 v1, v2…를 자동으로 붙인다. 버전마다 한 줄 메모(예: "B003 교차로 우회").
- **선정**: 분석 안에서 보고에 올릴 버전들. 안마다 하나로 제한하지 않는다(같은 안의 개선 전·후 비교 가능).
- 작업(JobInfo)에는 분석 ID·안 ID·버전 번호·메모가 붙는다. 기존 `Project`/`Plan` 필드는 남기고 기본값 제안에 쓴다.

### 4.2 ZWCAD에서 보내기

- `AGVSEND`(그리고 AutoMod 없는 PC의 `AGVMODEL` → 서버 전송)는 보내기 전에 창을 띄운다: 분석 선택(+ 새로 만들기), 안 선택(+ 새로 만들기), 버전 메모. 다음 버전 번호를 미리 보여 준다.
- 목록은 서버 API로 받는다. 처음 보내는 도면이면 폴더 이름·도면 이름과 같은 이름의 분석·안을 기본으로 고른다. 같은 도면에서 지난번 고른 분석·안을 기억해 다음에 기본으로 둔다(도면 폴더의 설정 파일).
- 서버에 연결되지 않으면 보낼 수도 없으므로 창은 서버 응답 뒤에 뜬다.
- `AGVRESULTUP`(PC 결과 올리기)도 같은 창을 쓴다.

### 4.3 웹

- 메인 메뉴에 **분석**을 추가한다. 분석 목록 → 분석 화면.
- 분석 화면: 안별 버전 목록(버전, 날짜, 보낸 사람, 메모, 권장 대수, 핵심 KPI, 상태), 선정 체크, 선정된 버전들의 비교 표, 컷 영상 진입.
- 이미 있는 작업(분석 없음)은 "미분류"에 모이고, 분석·안으로 옮길 수 있다.
- 분석·안 만들기·이름 바꾸기·작업 옮기기·선정은 **로그인 없이** 누구나 한다(작업 보내기와 같은 수준). 분석 삭제는 비어 있을 때만.
- 비교 표의 지표와 단위는 결과 화면의 결론 표와 같은 것을 쓴다.

## 5. 결론 동영상(컷)

### 5.1 흐름

1. ZWCAD가 보낼 때 도면을 DXF로 함께 올린다(아래 5.2).
2. 서버 빌드 시 DXF를 AutoMod 모델의 고정 그래픽으로 넣는다(5.3). 기존 대수 탐색은 그대로.
3. 사용자가 분석 화면에서 컷 편집기를 연다. 컷 리스트는 **분석에 속한다**. 바탕 도면은 선정된 버전 중 하나(기본: 가장 최근)의 DXF와 경로.
4. 내보내기: 고른 컷 × 고른 버전마다 서버가 그 버전의 모델을 촬영용으로 다시 실행해(기록 켜기, 결론 대수·시드) AutoView로 컷을 만든다.
5. 결과 MP4는 분석 화면과 각 작업 화면에서 재생·다운로드한다.

### 5.2 DXF 업로드

- 플러그인이 보내기 직전에 현재 도면을 DXF로 저장해 패키지에 넣는다(`drawing.dxf`). 크기 제한 안에서. 회사 문서 암호화가 DXF에도 걸리는지는 시험 필요(걸리면 ZWCAD가 쓴 직후 읽을 수 있는지 확인).
- 서버는 DXF를 편집기용으로 단순화한다: 선·폴리라인·원·호·글자를 SVG(또는 JSON 선분)로 변환해 저장. 블록 참조는 펼친다. 레이어 켬/끔은 편집기에서.
- 좌표는 모델 좌표계로 맞춘다: `ash.settings.tsv`의 Origin·Scale(도면 단위 → m)과 0.18의 단위 규칙(`ExportOptions.ToModel`)을 그대로 적용. 서버는 이 값을 모르므로, 플러그인이 패키지에 Origin·Scale·Units만 담은 작은 파일을 같이 보낸다(AmHome은 보내지 않음).

### 5.3 DXF를 영상에 넣기 (시험 필요)

- AutoView는 모델 그래픽만 찍는다. 도면이 영상에 나오려면 AutoMod 모델에 고정 그래픽으로 들어가야 한다.
- 방법 후보(빌더가 시험으로 고른다): AutoMod가 읽는 고정 그래픽 셀(.cel 등)로 DXF를 변환해 모델에 넣기, 또는 AutoMod의 DXF 가져오기 기능을 배치로 쓰기. 선·폴리라인 정도면 충분하다(채움 불필요).
- 안 되면: 영상 배경 없이 진행하고 사용자에게 알린다(편집기 배경은 그대로). 이 판단은 첫 단계 시험 결과로 한다.

### 5.4 컷

공통 값: 이름, 종류, 시작 시각(시뮬레이션 시각, 워밍업 포함 절대 시각), 배속, 기울기(0~70°, 0 = 바로 위), 바라보는 방향(0~359°, 편집기는 네 방향 버튼 + 수치), 원근 켬/끔, 자막 켬/끔.

- **구역 고정**: 사각형 A, 촬영 시간(시뮬레이션 초).
- **A → B 이동**: 사각형 A·B, A에서 N초, 이동 M초, B에서 L초(모두 시뮬레이션 초).
- **전체**: 사각형 = 레이아웃 전체(편집기가 자동으로 채움). 나머지는 구역 고정과 같다.
- 영상 길이 = 시뮬레이션 초 ÷ 배속. 편집기가 바로 보여 준다.
- 컷은 모델 좌표(m)로 저장한다. 같은 분석의 버전끼리 레이아웃 원점이 다르면 비교 컷이 어긋나므로, 버전 간 레이아웃 범위가 크게 다르면 편집기에서 경고한다(자동 보정은 하지 않음).

### 5.5 결과에서 찾는 장면 (컷 후보)

결과에서 자동으로 찾아 편집기의 "장면 후보"로 보여 준다. 누르면 컷으로 추가되고, 구역은 해당 위치 주변으로 잡힌다.

- **공급 0회 구간**: 자재 재고가 0인(결품) 구간. 시작·끝 시각과 해당 unload CP 위치.
- **지연 급증**: 호출 → 공급 시간이 그 자재 평균보다 크게 긴 호출(기준값은 빌더가 정하되 화면에 표시, 예: 평균의 3배 이상 또는 상위 1%).
- **병목**: block 대기 시간이 가장 큰 시간대와 그 block 위치.
- **전체 영상**.

지금 결과 파일은 집계값만 있어서 시각 정보가 부족하다. 모델 로직이 이벤트 로그(호출·공급 완료 시각과 자재, 결품 시작·끝, block 대기 시작·끝 중 필요한 것)를 남기도록 늘린다. 로그 크기가 커지지 않게 필요한 것만, 결론 실행(촬영용 재실행)에서만 남겨도 된다.

### 5.6 촬영 (서버)

`docs/autoview-guide.md`의 규칙을 따른다. 핵심:

- 촬영용 재실행: 그 버전의 결론 대수·시드로 모델을 다시 돌리되 기록(autoview)을 켜고, 필요한 시간 구간만 기록한다(CONTROL 줄 분할).
- 카메라 스크립트: 사각형 → 뷰 값은 가이드 4장 공식(평면). 기울기·방향은 카메라 위치를 구역 중심에서 해당 각도로 옮기고 upvector를 바꾼다(미검증 → 첫 단계 시험). 원근은 `perspective`/`orthogonal`.
- 좌표 단위는 µm, 배속 = 0.5 × time scale × fps(서버에서 프레임 수로 검증).
- 컷 1개당 AutoView 1회(`aview64 -n`, 작업 폴더 분리, `camera.des` 고정 이름), 대화상자 자동 클릭, `aviewerr.dat` 검사, `NoDefaultCurrentDirectoryInExePath` 제거, ffmpeg 필요.
- 후처리(ffmpeg): 휴대폰·PPT 호환(H.264, yuv420p, faststart), 자막 입히기, 이어 붙이기.
- 촬영은 작업 큐에서 순서대로 한다. 대수 탐색과 동시에 돌지 않게 하고, 컷 하나가 멈추면 시간 제한으로 끊고 다음으로 넘어간다.
- 서비스 세션(로그온 없음)에서 렌더가 되는지는 서버에서 확인해야 한다. 안 되면 대안을 사용자에게 묻는다(예: 작업 스케줄러로 로그온 세션에서 실행).

### 5.7 내보내기

- 고를 것: 컷(여러 개), 버전(분석의 선정 버전 중 여러 개), 해상도(1280×720 / 1920×1080), 프레임(15/30), 파일 형태(컷별 + 이어 붙인 1개 / 이어 붙인 1개 / 컷별), 자막.
- 파일 이름에 분석·안·버전·컷 이름을 넣는다.
- 결과는 분석 화면의 "영상" 목록에 남고, 웹에서 재생(휴대폰 포함)·다운로드한다.

### 5.8 편집기 화면

시안(위 링크)이 기준이다. 사용자 피드백: **PC 웹 화면 기준으로 배치를 잘 맞출 것**.
- PC: 도면을 크게(화면 폭의 2/3 이상), 오른쪽에 컷 설정, 아래에 컷 리스트·장면 후보·내보내기. 스크롤 없이 도면과 컷 설정이 한 화면에 보이게.
- 휴대폰: 세로로 쌓기. 보고 확인하는 용도가 중심(편집도 가능하면 좋음).
- 도면: 확대·이동(휠은 기울이기에 쓰므로 확대는 버튼 또는 Ctrl+휠), 레이어 켬/끔, 사각형 그리기·고치기, 기울기 미리보기(근사).
- 외부 CDN 금지(사내망). 필요한 스크립트는 서버에 같이 넣는다.

## 6. 제약

- 사내망: 웹 페이지는 외부 자원을 불러오지 않는다.
- 서버는 Windows 서비스로 돈다. AutoMod·AutoView 14.5(폴더 이름 12_6). ffmpeg를 서버에 둬야 한다(배포 방법은 빌더 결정, 라이선스 확인).
- 이 개발 PC의 AutoMod는 Student 판이라 일부 대화상자가 다르다. 최종 확인은 서버.
- 기존 작업·결과 화면·API와 0.18 플러그인의 보내기는 계속 동작해야 한다(새 필드가 없으면 "미분류").

## 6.1 촬영 조건 (사용자 결정, 2026-10-23)

- **대수**: 기본은 각 버전의 결론 대수. 컷 또는 내보내기에서 바꿀 수 있다: "결론 −N대", 또는 "모든 버전 같은 대수(그룹별 지정)". 바꾸면 그 대수로 다시 돌려 찍는다. 결론 대수에서는 결품이 원칙적으로 없으므로, 리스크 장면은 줄인 대수로 보여 주는 것이 주 용도다.
- **시드**: 각 버전의 첫 시드(SeedBase)로 찍고, 같은 내보내기의 모든 버전에 같은 시드를 쓴다. 필요하면 다른 시드를 고른다.
- **자막 수치**: 그 버전의 결론 지표(결론 표와 같은 평균값, 예: "권장 7대 · 가동률 68% · 결품 0초"). 대수를 바꿔 찍은 컷은 그 대수의 탐색 결과가 있으면 그 값을, 없으면 촬영 실행의 값을 쓰고 자막에 "이 실행 1회 값"이라고 밝힌다.

## 6.2 장면 후보를 찾는 시점 (내 결정)

- 대수 탐색이 끝나면 결론 대수·첫 시드로 이벤트 로그를 켠 실행을 자동으로 1회 더 돌려 후보를 미리 찾아 둔다(큐 시간이 실행 1회만큼 늘어남).
- 다른 대수의 후보는 편집기의 "후보 찾기"로 그때 돌린다.
- PC에서 올린 결과(AGVRESULTUP)는 자동 실행을 하지 않고 "후보 찾기"로만.
- 후보는 선정된 모든 버전에서 찾고 버전 표시를 붙인다(개선 전 버전의 문제 장면을 개선 후 버전에 같은 컷으로 적용하는 것이 핵심 용도).
- 이벤트 로그는 모델 로직에 들어가므로 새 플러그인으로 만든 모델에만 있다. 로그가 없는 모델은 "후보 없음(새 버전으로 다시 보내면 생김)"을 알린다.

## 7. 빌더에게 맡기는 것

- 저장 방식(파일/JSON 등)과 API 모양, 화면 세부 디자인.
- DXF 파싱 라이브러리 선택 또는 직접 구현(선·폴리라인·원·호·글자·블록 수준).
- 지연 급증의 기준값, 장면 후보 구역 크기.
- 이벤트 로그 형식.
- 촬영 큐와 대수 탐색 큐의 관계(같은 큐/별도 큐).

## 8. 먼저 시험해서 확인할 것 (설계를 바꿀 수 있음)

1. 기울인 시점에서 사각형이 화면에 맞게 담기는 카메라 값 계산(이 PC).
2. DXF를 AutoMod 고정 그래픽으로 넣어 AutoView 영상에 나오게 하는 방법(이 PC).
3. 회사 문서 암호화가 플러그인이 쓴 DXF에 걸리는지(회사 PC).
4. 서버 서비스 세션에서 AutoView 렌더(운영 서버).
