# ASH 분석 서버 설계: 에셋 공유, 서버 실행, 웹 결과

작성일: 2026-10-21
상태: 초안 (사용자 승인 전)
선행 설계: `2026-10-20-ash-plugin-design.md` (이하 "ASH 설계"). 이 문서는 ASH 설계에 서버를 더한다. 겹치는 내용은 이 문서가 우선한다.

## 1. 의도와 배경

AGV 수량 산출 작업은 다음 순서로 진행된다(사용자 설명).

도면 정리 → 자재 정보 정리 → path 작성 → CP 배치 → 로직 구성 → segments·vehicle 생성 → 1차 검증(경로·자재 정보 오류) → 수정 → 2차 검증(AGV 수량과 부하율 적정선) → 보고서 → 완료

지금은 차량(vehicle), 세그먼트(segment), 외형 그래픽(`.cel`) 같은 에셋을 각자 PC에 저장해 쓴다. 그래서 다음 문제가 생긴다(사용자 경험).

- 에셋이 없으면 가진 사람을 찾아다녀야 한다.
- 누군가 작업한 1안을 넘겨받아 2안을 작업할 때 에셋이 없어 새로 만들고, 그 결과 AGV 형상이 1안과 달라진다.
- 외형을 최신화해도 다른 사람에게 공유하기 어렵다.

해결 방향: 사내 Windows 서버 한 대에 웹 서버를 띄운다. 에셋, 공용 로직, 자재 정보를 서버 한 곳에서 버전으로 관리한다. ASH(ZWCAD 플러그인)가 만든 도면과 설정을 서버로 보내면 서버가 AutoMod(이하 AM)를 빌드·반복 실행해 적정 대수를 찾고, 결과를 웹에서 보여 주고 내려받게 한다.

## 2. 목표, 비목표, 금지 목표

### 목표

1. 차량·세그먼트·외형(`.cel`) 에셋과 공용 로직을 서버에서 버전으로 관리한다. 누구나 고칠 수 있고, 모든 변경은 새 버전으로 남는다.
2. STEP 파일을 올리면 단순화한 `.cel` 외형으로 변환한다.
3. 자재 정보를 Excel로 올린다. 샘플 양식을 제공한다. 법인 / 제품군 / 라인으로 걸러 보고, 다른 분석에서 쓴 자재 정보를 가져다 쓴다.
4. ASH의 버튼 하나로 프로젝트 폴더의 필수 파일을 서버에 올리고, 서버가 대수 최적화(수십~백여 회 실행)를 한다.
5. 결과를 웹에서 "결론 먼저"로 보여 주고 PPTX·XLSX·원본을 내려받게 한다.
6. 서버가 바쁘면 사용자가 지금처럼 자기 PC에서 실행할 수 있다(ASH.Runner 유지).

### 비목표 (v1에서 하지 않음)

- 인터넷 공개, 사내망 밖 접속.
- 계정·비밀번호·권한 체계. 사용자는 IP와 최초 접속 시 입력한 이름으로만 구별한다(관리자만 예외, 7장).
- 웹에서 도면이나 경로 편집. 레이아웃 편집은 ZWCAD(ASH)에서만 한다.
- 웹에서 공용 로직을 코드 편집기로 편집. 파일 업로드·다운로드와 버전 간 차이 보기만 제공한다.
- 웹에서 실시간 애니메이션. 영상은 요청 시 AutoView로 만든 MP4로만 본다.
- 결과 히트맵에 공장 배경 도면 그리기. v1은 경로·block·CP만 그린다.
- AGV 이외의 이동 시스템(ASH 설계와 같다).

### 금지 목표 (이렇게 되면 실패)

- 결과가 어떤 에셋 버전·공용 로직 버전·자재 버전·시드에서 나왔는지 추적할 수 없다.
- 누군가 에셋이나 공용 로직을 고쳤는데, 진행 중이거나 끝난 다른 프로젝트의 입력이 조용히 바뀐다.
- 대화상자 하나 때문에 서버 실행이 멈추고, 대기열 전체가 영원히 막힌다.
- 서버를 쓰면 로컬에서 할 때보다 결과를 받기까지 사람 손이 더 든다.

## 4. 전체 구성

ASH 솔루션(같은 저장소, 13장)에 프로젝트 두 개를 더한다. 신규 프로젝트는 C#, .NET 10이다. `ASH.Core`는 플러그인(net48) 때문에 지금처럼 .NET Standard 2.0으로 두고 함께 쓴다.

- 배포: win-x64 자가 포함 단일 파일 (AGV_FOTA_GATEWAY와 같은 방식)

```
ASH.Core      (기존) .asy Writer, Excel 스키마, 공용 로직 템플릿, 결과 파서, 판정, ModelRunner
ASH.Plugin    (기존) + "서버로 보내기" 버튼, 서버 대기열 표시, 에셋 내려받기
ASH.Runner    (기존) 로컬 실행 유지
ASH.Server    (신규) ASP.NET Core 웹. 화면, 파일 저장, DB, 대기열, 결과 가공, 보고서 생성
ASH.Worker    (신규) AM 빌드·실행 전담 프로세스. 서버 DB의 대기열에서 작업을 가져와 처리
```

- `ASH.Server`는 Windows 서비스로 실행한다.
- `ASH.Worker`를 웹과 분리하는 이유: AM 실행 방식(서비스 / 로그온 시 실행)을 웹과 따로 바꿀 수 있어야 하고(8.4), 워커가 죽어도 웹은 살아 있어야 하기 때문이다.
- 저장소: 데이터 폴더(예: `D:\ASHData\`) 아래 파일 + SQLite DB 하나. 파일은 내용 해시로 저장해 같은 파일을 두 번 저장하지 않는다.

## 5. 데이터 모델

모든 "버전" 객체는 한 번 저장하면 바뀌지 않는다(불변). 고치면 새 버전이 생긴다.

| 객체 | 내용 | 버전 관리 |
|---|---|---|
| 차량 에셋 (VehicleAsset) | 이름, AGV_Types 행의 제원(속도·가감속·적재/하역 시간·MTBF/MTTR·길이·폭·색), 세그먼트 정의(`AGVVEHSEG`), 외형 `.cel`, 미리보기 PNG, 원본 STEP(있으면) | 있음 |
| 공용 로직 (CommonLogic) | `code.m` 템플릿과 `params.txt` 스키마 버전 | 있음 |
| 자재 세트 (MaterialSet) | 법인, 제품군, 라인, 이름, Materials 행 목록, 원본 Excel | 있음 |
| 프로젝트 (Project) | 이름, 법인/제품군/라인, 작성자 | 아래 "안(案)"을 가진다 |
| 안 (Scenario) | 1안·2안. 업로드 파일(`agv.asy`, `input.xlsx`, `user_ext.m`, 경량 DXF, 원본 DWG), 고정된 차량 에셋 버전 목록, 공용 로직 버전, 자재 세트 버전 | 업로드마다 새 리비전 |
| 작업 (Job) | 안 리비전 하나에 대한 최적화 요청. 상태, 진행률, 요청자 | - |
| 실행 (Run) | 그룹별 대수 조합 + 시드 + 결과 파일 | - |

**정본 규칙(설계자 결정, 빌더 확인 질문 반영)**

- **서버가 모델을 다시 조립한다.** 업로드 파일은 "레이아웃과 프로젝트 입력"이고, 차량·공용 로직·자재는 안에 고정된 서버 버전이 정본이다. 워커는 조립할 때 `agv.asy`의 `AGVVEHSEG`·차량 그래픽, `input.xlsx`의 AGV_Types·Materials를 서버 버전 값으로 다시 쓰고, Process `.asy`와 `params.txt`를 `ASH.Core`(`ModelBuilder` 등)로 새로 만든다.
- **차량 에셋 짝짓기 키**: AGV_Types의 `Type` 이름 = 차량 에셋 이름. 에셋에 없는 Type이면 보내기 창이 "새 에셋으로 등록"을 제안한다. 같은 이름인데 업로드 값이 서버 고정 버전과 다르면 보내기 창이 차이를 보여 주고 "서버 값 사용(기본)" 또는 "업로드 값으로 새 에셋 버전 등록"을 고르게 한다.
- **자재 정본**: 안은 자재 세트 버전 하나에 연결된다. 업로드한 `input.xlsx`에 Materials 시트가 있으면 새 자재 세트 버전을 만들고 연결을 바꾼다. 보내기 창은 바꾸기 전에 "웹에서 연결한 자재 세트를 업로드한 것으로 바꿉니다"를 알린다. 서버 양식의 `Corp`·`ProductLine`·`Line` 열은 ASH 양식에 있어도 무시되는 추가 열이다(ASH 양식 리더는 모르는 열을 무시해야 한다).
- **block·교통제어 정보**: `agv.asy`에는 block 사각형과 block↔진입 CP 표(`traffic.tsv`)가 없다. 그래서 ASH 내보내기가 `blocks.tsv`(이름, cap, 사각형 좌표)를 함께 만들고, 둘 다 필수 업로드에 넣는다(6.5). 히트맵도 이 파일로 그린다.

- **복사로 시작**: 2안은 1안을 복사해 만든다. 고정된 에셋·로직·자재 버전도 그대로 복사된다.
- **버전 갱신은 사용자가 고른다**: 안이 쓰는 에셋에 새 버전이 나오면 안 화면에 "새 버전 있음"을 표시하고, 사용자가 누르면 그 안만 새 버전으로 바꾼다. 자동으로 바꾸지 않는다(금지 목표).
- **되돌리기**: 예전 버전을 골라 "이 버전으로 복원"하면 그 내용으로 새 버전을 만든다. 기록은 지우지 않는다.
- 모든 버전에는 작성자(이름+IP), 시각, 변경 메모(선택)를 남긴다.

## 6. 기능

### 6.1 에셋 라이브러리

- 목록: 이름, 최신 버전, 마지막 수정자, 미리보기 이미지. 법인·제품군·라인 태그로 거른다.
- 상세: 제원 편집 폼, 세그먼트 표, 외형 미리보기, 버전 이력(버전 간 바뀐 필드 표시).
- 누구나 생성·수정할 수 있다. 삭제는 "숨김"만 있고, 숨겨도 그 에셋을 쓰는 안은 그대로 동작한다.
- **일괄 이관**: 각자 PC에 있는 기존 차량 정의(`.asy`에서 추출)와 `.cel` 파일을 여러 개 한꺼번에 올리는 화면. 이름은 같은데 내용이 다르면 둘 다 보관하고(`이름 (2)`), 사용자가 나중에 하나를 고르거나 합친다.
- ASH 플러그인은 서버의 에셋 목록을 받아 Excel의 AGV_Types 행을 채우고, 내보내기 때 `.cel`을 모델 폴더에 복사한다.

### 6.2 STEP → `.cel` 변환

- 업로드한 STEP을 서버가 읽어, 부품(솔리드)마다 축 정렬 상자 하나로 바꾼다. 원통형으로 판별되는 부품(바퀴 등)은 원기둥으로 바꾼다. 부품 색은 유지한다.
- 단순화 옵션: 최소 부품 크기(기본: 전체 길이의 2% 미만 부품 제거), 최대 도형 수(기본 200), 상자/원기둥만 사용.
- 결과는 미리보기 PNG(위·옆·사선 3방향)와 `.cel`로 저장하고, 사용자가 확인한 뒤 에셋 버전으로 저장한다.
- 원점·방향 규칙: AM 차량의 진행 방향과 바닥 기준에 맞춰 회전·이동한다. 사용자가 미리보기에서 90° 회전과 원점 위치(앞/중심/뒤)를 고칠 수 있다.
- STEP 해석에는 기하 커널이 필요하다. 라이브러리 선택은 빌더에게 맡기되, 서버에 오프라인으로 설치되고 실행 시 외부 네트워크가 필요 없어야 한다.
- **관문 G3(11장)**: `.cel` 타입 코드(310 상자, 원기둥 후보 320/321/350/351)의 필드 의미를 데모 파일과 AM 화면 비교로 확정한다. 확정 전에는 상자(310)만 쓴다.

### 6.3 공용 로직

- 공용 로직(`code.m` 템플릿)도 에셋처럼 누구나 새 버전을 올릴 수 있다. 웹은 파일 업로드·다운로드, 버전 간 차이(diff) 보기, 변경 메모를 제공한다.
- 새 버전을 올리면 서버가 기준 모델(`agvdemo` 기반 테스트 모델)로 빌드를 시험해 "빌드 통과/실패" 표시를 붙인다. 실패 버전도 저장은 되지만 안에서 고를 때 경고한다.
- 프로젝트별 특수 로직은 지금처럼 안의 `user_ext.m`에만 둔다.
- 공용 로직에는 `params.txt`의 `Debug` 값(기본 0)을 두고, `print` 출력은 `Debug=1`일 때만 하게 바꾼다. 메시지 창 출력이 실행을 크게 늦추기 때문이다(3장).

### 6.4 자재 정보

- 샘플 양식: 서버가 ASH 설계 7.1의 Materials 시트를 바탕으로 만든다. 열: `Corp`(법인), `ProductLine`(제품군), `Line`(라인), `Material`, `Station`, `Group`, `TaktTime`, `UnitsPerCycle`, `UnitsPerContainer`, `CallThreshold`, `UnloadThreshold`, `InitStock`, `SafetyStock`, `EmptyReturn`. 2행은 설명·단위, 3행부터 입력 예시 3줄.
- 업로드 검증: 필수 열 누락, 숫자 범위, 같은 세트 안 자재 코드 중복, 알 수 없는 값(`EmptyReturn`은 Y/N). 문제 행은 웹에 행 번호와 이유로 표시하고, 오류가 있으면 저장하지 않는다. 경고만 있으면 저장할 수 있다.
- 검색: 법인 / 제품군 / 라인 필터 + 자재 코드·공정명 검색. 다른 안에서 쓴 자재 세트도 같이 나온다.
- 가져오기: 다른 세트의 자재를 골라 내 안으로 가져오면 **복사본**이 된다. 원본이 나중에 바뀌어도 내 안은 바뀌지 않는다.
- ASH가 올린 `input.xlsx`에 Materials 시트가 있으면, 서버는 이를 새 자재 세트 버전으로 등록하고 그 안에 연결한다.

### 6.5 ASH에서 서버로 보내기

- ASH 팔레트와 리본에 "서버로 보내기" 버튼을 둔다. 서버 주소는 `ash.settings.tsv`의 `ServerUrl`.
- 버튼을 누르면 ASH가 프로젝트 폴더(ASH 설계 4장 구조)에서 필수 파일을 자동으로 찾는다.
  - 필수: `<Model>.arc\agv.asy`, `<Model>.arc\blocks.tsv`, `<Model>.arc\traffic.tsv`, `input.xlsx`
  - 있으면 함께: `<Model>.arc\user_ext.m`, `lite\*.dxf`, `layout.dwg`
  - 필수 파일이 없으면 무엇이 없는지 알려 주고 보내지 않는다.
- 보내기 창에서 프로젝트·안을 고르거나 새로 만들고, 법인/제품군/라인을 고른다. 처음 보내는 안이면 차량 에셋과 공용 로직은 최신 버전으로 고정한다.
- 보내기 전에 서버 대기열 상황(앞에 있는 작업 수, 예상 시작 시각)을 보여 준다. 사용자는 "서버 실행" 또는 "로컬 실행(ASH.Runner)"을 고른다.
- 로컬에서 실행한 결과(`runs\summary.tsv`와 실행 폴더)는 "결과 올리기" 버튼으로 서버에 올려 같은 결과 화면으로 볼 수 있다(설계자 결정).
- 로컬 결과의 추적성(설계자 결정): ASH가 로컬 실행에 쓴 차량 정의·공용 로직·자재의 내용 해시를 함께 올린다. 서버는 해시가 서버의 어떤 버전과 같으면 그 버전으로 기록하고, 같은 것이 없으면 결과 화면에 "버전 미확인(로컬 실행)" 표시를 붙인다. 로컬 실행 전에 서버 버전을 강제로 내려받게 하지는 않는다.

### 6.6 대기열과 실행

- 작업은 선착순. 취소는 작업을 올린 사람(같은 IP)과 관리자만 할 수 있다.
- `ASH.Worker`가 작업을 하나씩 가져와 처리한다.
  1. 안 리비전의 파일, 고정된 에셋·로직·자재 버전으로 작업 폴더에 모델을 조립한다.
  2. 그룹별 `MaxCount`로 한 번 빌드한다(`am264.exe -bq`). 빌드 오류면 오류 내용을 결과에 붙이고 끝낸다.
  3. 탐색(6.7)이 정한 순서로 `params.txt`를 바꿔 `<Model>.exe -w`를 실행한다. 동시 실행 수는 서버 설정값(기본 2, 관리자가 조정).
  4. 실행마다 시간 제한(기본: 측정된 1회 시간의 5배, 최소 10분)을 넘기면 프로세스를 강제 종료하고 실패로 기록한 뒤 다음으로 넘어간다.
- 실행 하나가 끝날 때마다 결과를 DB에 올려 웹에 진행률, 남은 시간, 중간 결과가 보이게 한다.
- 실행 출력(`stdout.dat`, `.message`)이 일정 크기(기본 1 MB)를 넘으면 결과 화면에 "로직에 디버그 출력이 남아 있음" 경고를 붙인다.

### 6.7 대수 탐색

그룹 간 경로 공유 때문에 그룹을 독립으로 볼 수 없다(사용자). ASH 설계 8.2를 아래로 바꾼다.

1. **묶음 나누기**: `agv.asy`의 경로 그래프에서 각 그룹이 Routes의 CP 사이를 오갈 때 쓰는 구간(최단 경로)과 block을 구한다. 구간이나 block을 하나라도 같이 쓰는 그룹은 같은 묶음이다. 다른 그룹과 공유가 없는 그룹은 혼자 묶음이 된다.
2. **묶음별 좌표 하강**: 모든 그룹을 `MaxCount`에서 시작한다. 묶음 안 그룹을 차례로 하나씩, 판정을 통과하는 한 대수를 줄인다(그룹 하나에 대해서는 이진 탐색). 판정은 **묶음 안 모든 그룹**에 대해 한다. 한 그룹을 줄였을 때 다른 그룹이 판정에 떨어지면 그 감소는 채택하지 않는다. 한 바퀴 돌아 바뀐 것이 있으면 바뀐 것이 없을 때까지 다시 돈다.
3. **반복 수**: 탐색 중에는 반복 1회, 결정값과 그 -1에서는 `Replications`(기본 3)회. 주의: 2차 구현 기록에 따르면 지금 공용 로직에는 AM 쪽 난수가 없고, 시드는 Core의 초기재고 분산에만 쓰인다. 그래서 반복 결과 차이는 초기재고 분산에서만 나온다. 신뢰구간 띠는 이 범위의 변동만 뜻한다는 점을 결과 화면에 적는다. 고장(MTBF) 난수가 들어오면(3차) 시드별 재빌드 비용을 워커 예산에 반영한다.
4. **확인 실행**: 전 그룹 권장 조합으로 `Replications`회 실행해 판정한다. 실패하면 판정에 떨어진 그룹을 +1 하고 다시 확인한다.
5. **판정 규칙**(ASH 설계 8.2와 같다): 재고 ≥ 안전재고 → 가동률 ≤ `UtilMax` → 공급 횟수 ≥ 기대치의 95% → 교착 경고 0.
6. **영향표 실행(선택, 기본 켜짐)**: 확인 실행 후 그룹마다 권장 대수 +1을 `Replications`회 실행해, 다른 그룹 부하율 변화를 기록한다. 20개 그룹이면 60회, 1회 2분·동시 2개 기준 약 1시간이 더 든다.

권장 대수 정의: 판정을 모두 통과하는 최소 대수 조합.

### 6.8 결과 화면

시안 이미지 `docs/images/result-summary-mock.png`(결론 탭), `docs/images/result-detail-mock.png`(상세 탭)를 기준으로 한다. 이미지의 숫자는 가짜 샘플이다. 시안 뒤에 결정된 히트맵 2종(점유율·대기시간)과 영향표·공유 구간 지도는 시안에 없다.

**결론 탭** (경영진용, 결론 먼저)

- 맨 위 카드 3개: 권장 AGV 총 대수와 시험 범위(ΣMinCount~ΣMaxCount). "현재안 대비 증감"은 비교 기준값이 없어 넣지 않는다(ASH 세션 협의, 2026-10-21). 나중에 필요하면 AGV_Groups에 선택 열 `CurrentCount`를 더하고 값이 있을 때만 "현재 대비"를 표시한다, 평균 부하율(상한 대비, 초과 그룹 수), 최대 병목 지점(이름, 평균 대기, 점유율).
- 그룹별 권장 대수와 부하율 표. 막대에 상한선 표시, 판정 실패·경고 그룹은 표시.
- 병목 히트맵 **2개**: 점유율 기준, 대기시간 기준(사용자 결정). 권장 조합 기준. 경로 구간과 block을 색으로 칠하고 공정 CP를 표시한다. 가장 심한 지점에 이름과 값을 단다.

**상세 탭**

- 그룹 선택 → 대수별 부하율 곡선(반복 평균 + 95% 신뢰구간 띠, 상한선, 권장 대수 표시, 결품 발생 대수 표시).
- 대수 슬라이더가 있는 히트맵 2개(점유율, 대기시간). 슬라이더를 움직이면 같은 묶음의 다른 그룹 부하율 막대도 같이 바뀐다(해당 조합의 실행 결과가 있을 때만. 없으면 "실행 안 함"으로 표시).
- **영향표**(사용자 결정: 상세 탭): 행 = +1대 늘린 그룹, 열 = 다른 그룹의 부하율 변화(%p). 칸 색 진할수록 영향 큼.
- **공유 구간 지도**: 그룹을 고르면 그 그룹이 쓰는 구간을 진하게, 다른 그룹과 겹치는 구간을 테두리로 표시. 병목 block을 누르면 그룹별 대기 원인 비율("대기의 60%는 G03")을 보여 준다.
- 전 그룹 대수별 부하율 막대 비교.
- 자재 재고 위험 상위 N개, 리스크 목록(ASH 설계 8.3의 4~5).

**입력·에셋 탭**: 이 결과를 만든 파일, 에셋·로직·자재 버전, 시드, 반복 수, 실행 목록. 결과 추적용이다.

**다운로드 탭**: PPTX 보고서(ASH 설계 8.3 구성), XLSX(요약과 실행별 결과), 원본 실행 파일 ZIP(보관 기간 안에서만), 영상.

히트맵 기하는 `agv.asy`의 경로 좌표와 block 사각형에서 그린다. 그룹별 대기 원인 비율을 위해 공용 로직의 `result.tsv`에 "block별·그룹별 대기 시간" 항목을 더한다.

### 6.9 보고서와 영상

- PPTX와 XLSX는 작업이 끝나면 자동으로 만든다.
- 영상은 결과 화면의 "영상 만들기" 버튼을 눌렀을 때만 만든다. 이 작업도 대기열에 들어간다.
- **영상은 AutoView로 만든다(사용자 결정, 2026-10-21).** 화면 녹화(ffmpeg gdigrab)는 쓰지 않는다. ASH 설계 8.4의 "화면 녹화 기본"을 대체한다.
  1. 워커가 권장 조합의 모델을 AutoView 출력을 켠 상태로 창 없이(`-w`) 한 번 더 실행해 `<Model>.avw`를 만든다. AutoView 출력은 `model.amo`의 `CONTROL snaplen 8 Hours counts 1 autorep autoview` 줄에서 `autoview` 토큰 유무로 켜고 끈다(데모 `agvdemo.arc/model.amo` 원문). ASH `ModelAmoWriter`의 `AutoView` 옵션(ASH 2차 Task 5b)을 쓴다.
  2. 워커가 카메라 스크립트를 생성한다. 내용: `FORMAT MP4`, 파일 이름·해상도·폴더, `FRAMESPERSEC`(기본 15), `TIME SCALE`(배속), 시점(`VIEW`, `PAN`), `RECORD MP4`. 개요 영상 1개 + 병목 상위 N개 block 주변 확대 영상을 만든다. 병목 시점은 `blocks.tsv` 좌표로 정한다.
  3. 워커가 `aview64.exe`로 `.avw`와 스크립트를 열어 MP4를 만든다. 끝나면 프로세스를 종료한다. 시간 제한과 강제 종료는 6.6과 같다.
  4. 배속 캡션은 카메라 스크립트로 넣을 수 있으면 넣고, 안 되면 v1에서는 영상 파일 이름과 결과 화면에 배속을 적는다.
- 카메라 스크립트 문법은 AutoView 도움말과 설치본 문자열(`RECORD MP4`, `GENERATE MP4`, `MP4 <파일> <가로> <세로> <폴더> <true|false>`, `FRAMESPERSEC`, `SAVEFRAMES`)을 근거로 확정한다.

## 7. 사용자 구별과 관리자

- 최초 접속 시 이름을 묻고, 서버가 IP와 이름을 묶어 저장한다. 이후 그 IP의 모든 기록에 이름이 붙는다. 이름은 언제든 바꿀 수 있다.
- ASH 플러그인이 보내는 요청도 같은 IP로 구별되므로 같은 사람이 된다.
- 관리자: 서버 설정 파일의 IP 목록. 관리자는 다른 사람 작업 취소, 동시 실행 수와 시간 제한 변경, 숨긴 에셋 복원을 할 수 있다.
- **한계(사용자 수용)**: DHCP로 IP가 바뀌면 이름을 다시 입력해야 하고, 이전 기록은 이전 IP 이름으로 남는다. 다른 사람의 IP를 쓰면 그 사람으로 보인다. 공용 PC는 여러 사람이 한 이름으로 보인다.

## 8. 운영과 보안

### 8.1 접근 범위

- 사내망 전용. 서버 방화벽에서 웹 포트만 연다. HTTP로 시작한다(사내망). HTTPS가 필요하면 사내 인증서로 바꿀 수 있게 만든다.
- 외부 CDN, 외부 폰트, 외부 API를 쓰지 않는다. 화면에 필요한 JS·CSS는 모두 서버에 포함한다.

### 8.2 업로드 코드 실행 위험

`user_ext.m`과 공용 로직은 AM 빌드 때 C로 바뀌어 서버에서 컴파일·실행된다. 즉, 업로드할 수 있는 사람은 누구나 서버에서 임의 코드를 실행할 수 있다. 사내 도구로 받아들이되 피해를 줄인다.

- `ASH.Worker`는 관리자 권한 없는 전용 Windows 계정으로 실행한다. 이 계정은 데이터 폴더의 작업 영역과 AM 설치 폴더(읽기)만 접근한다.
- 웹(`ASH.Server`)은 업로드 파일을 실행하지 않는다. 실행은 워커만 한다.
- 업로드 크기 제한(기본 파일당 200 MB)과 확장자 검사.

### 8.3 백업

데이터 폴더와 SQLite DB를 매일 다른 디스크로 복사한다. 방법은 빌더가 정하되(예: 예약 작업), 웹 관리 화면에 마지막 백업 시각을 표시한다.

### 8.4 워커 실행 방식

- 기본: Windows 서비스(사용자 허락).
- 위험: 서비스는 화면 없는 세션(Session 0)에서 돈다. AM 빌드·실행 중 대화상자가 뜨면 아무도 닫을 수 없다. 6.6의 시간 제한과 강제 종료로 대기열이 막히지는 않게 한다.
- 관문 G1(11장)에서 문제가 확인되면 "로그온 시 실행" 방식으로 바꾼다. 서버를 전용 계정으로 자동 로그인하게 하고, 워커를 작업 스케줄러의 "로그온 시" 작업으로 띄운다. 이때는 ASH의 `DialogCloser`로 정보성 대화상자를 닫는다.
- 두 방식은 설정 하나로 바꿀 수 있게 만들고, 설치 스크립트가 양쪽을 모두 지원한다.

2. ZWCAD에서 ASH로 도면 경량화, path, CP, block을 작성하고 `AGVCHECK`한다.

4. ASH에서 서버의 차량 에셋을 골라 AGV_Types를 채우고, 내보내기를 한다.
5. "서버로 보내기"를 누른다. 대기열이 길면 로컬 실행을 고른다.
6. 웹에서 진행 상황을 보고, 끝나면 결론 탭을 확인하고 보고서를 받는다. 필요하면 영상 만들기를 요청한다.
7. 2안은 웹에서 1안을 복사하고, 도면을 고쳐 다시 보낸다.

## 16. ASH.Core 공개 API (ASH 2차 완료, `feat/core-and-layout` @ `a93c033`, ASH 세션 회신 2026-10-21)

서버 계획은 아래 API를 기준으로 세운다. 모두 netstandard2.0, InvariantCulture.

- 입력: `ExcelReader.Read(path, out List<Finding> warnings) → ProjectInput`, `InputValidator.Validate(ProjectInput, cpNames?) → List<Finding>`.
- 모델 생성: `ModelBuilder.Build(ModelBuildRequest(ProjectDir, ModelName, Input, Layout, ExportOptions, MaterialOverrides?, VehicleOverrides?, AutoView), amHome?, TimeSpan) → ModelBuildResult(ArcDir, Build?, Findings, Warnings)`. `ExportOptions.VehicleOverrides`(Type 이름 → `VehicleTemplateOverride(VehSegText?, VehicleBlockText?)`)와 `MaterialOverrides`로 서버 버전 값을 넣어 조립한다(5장 정본 규칙). 산출: `agv.asy`, `<Model>~.asy`, `model.amo`(`autoview` 토글), `params.txt`, `traffic.tsv`, `blocks.tsv`, `user_ext.m`, `arc\input.sig`.
- 실행: `ModelRunner.Run(RunRequest(...)) → RunOutcome`(예외 없음), `ModelRunner.PrepareWorkSlot(projectDir, model, slot)`(동시 실행 슬롯), `RunScenario(Seed, ActiveByGroup, Debug)`, `ParamsFile`. 서버는 `DialogButton`을 null(기본)로 둔다.
- 결과: `ResultParser`, `ResultSet`(Materials/Groups/Blocks/BlockGroups), `Kpi.FromRun → RunKpi[]`, `Judge.Evaluate → Verdict(Ok, Reason, RuleCode)`. 판정 순서: 정지시간>0 → 최소재고≥안전 → 가동률≤UtilMax → 소비량≥이론의 95% → 교착 0.
- 탐색: `ArcLayout.Load(arcDir)`, `GroupClusters.Build(Layout, ProjectInput, TrafficTable)`, `SearchStrategy.Search(ProjectInput, IRunExecutor, GroupClusters, SearchOptions, ct) → SearchResult(Decided, Trace, Impact, Warnings)`. `ParallelExecutor`(슬롯 N, `IProgress<RunOutcome>`)로 진행률을 웹에 올린다. `SummaryTsv`, `ImpactTsv`.

서버에서 주의할 점:
- `SearchOptions.ImpactTable` 기본값은 false다. 서버는 6.7의 "영향표 기본 켜짐"에 따라 true로 넘긴다.
- Core의 취소는 진행 중인 AM 프로세스를 죽이지 않는다. 6.6의 사용자 취소와 시간 제한은 워커가 프로세스를 직접 종료해 구현한다.
- 가동률은 `.report` 누적값이라 warmup을 포함한다(3차에서 제외 예정). 결과 화면에 이 사실을 적는다.
- AM 쪽 난수 시드가 없다(6.7 3번 주의와 같다).
- 3차 미결: warmup 제외 계측, MTBF, 버퍼 대기, AutoView 영상, 보고서. 서버의 PPTX·영상 기능은 ASH 3차 결과를 쓴다.

## 17. 버전과 자동 업데이트

- **하나의 버전 번호**: 플러그인·서버·워커·Core는 `Directory.Build.props`의 버전 하나(SemVer)를 같이 쓴다. 릴리스마다 태그를 단다.
- **업로드 형식 버전**: ASH가 서버로 보내는 묶음에 `manifest.json`(ASH 버전, 형식 버전, 파일별 내용 해시)을 넣는다. 서버는 받을 수 있는 형식 버전 범위를 가지고, 범위 밖이면 "ASH를 업데이트하세요"와 설치 파일 링크로 거절한다.
- **플러그인 자동 업데이트는 서버가 맡는다**: 서버가 최신 `ASH-Setup-x.y.z.exe`와 버전 정보(`/api/ash/version`: 최신, 최소 지원)를 제공한다. 사내 서버라 GitHub 접속이 필요 없다. ASH는 ZWCAD 시작 시와 "서버로 보내기" 때 이를 확인하고, 새 버전이 있으면 알린다. 실행 중인 ZWCAD는 플러그인 DLL을 잠그므로, 내려받은 설치 파일을 "ZWCAD 종료 후 설치"로 실행한다(설치 파일은 이미 ZWCAD 실행 중이면 설치를 거부한다). 최소 지원 버전보다 낮으면 서버 기능만 막고 로컬 기능은 계속 쓰게 한다.
- **서버 업데이트**: 새 버전 배포 시 대기열 접수를 멈추고, 진행 중인 작업이 끝나면 워커·웹을 교체하고 재시작한다. DB 스키마는 마이그레이션으로 올리고, 올리기 전에 DB를 백업한다.
- **재현성**: 작업마다 그 작업을 돌린 서버(Core) 버전을 기록한다. 결과 화면 "입력·에셋 탭"에 표시한다.
- **공용 로직 동기화**: 서버 실행은 서버의 공용 로직 버전을 쓴다. 로컬 실행 전에 ASH가 서버에서 그 안의 고정 버전(없으면 최신)을 내려받아 쓴다. 서버에 접속할 수 없으면 Core 내장 템플릿을 쓰고 결과에 "공용 로직: 내장"을 기록한다. 쓴 로직 버전은 `arc\input.sig`에 남긴다.
- **에셋 동기화(로컬 실행)**: ASH는 안에 고정된 차량 에셋 버전을 서버에서 내려받아 `VehicleOverrides`로 쓴다. 로컬 캐시에 두어 서버가 꺼져 있어도 마지막 받은 버전으로 실행할 수 있다.
