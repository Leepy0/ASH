## 0. 공통 전제

- **주 사용자**는 분석 담당자다. 자기 분석의 진행을 보고, 안·버전을 비교하고, 다음 버전을 계획하고, 보고용 영상을 만든다. 중간 관리자·실무자는 같은 화면을 열람한다. 경영진은 웹을 보지 않는다(PPT만).
- **PC 브라우저만** 대상이다. 폰 배치는 고려하지 않는다(깨지지만 않으면 됨). 기준 폭 1280~1920.
- 로그인 없음(서버 설계 2장). **"내 것"의 기준은 접속 IP + 보낸 사람 이름(Windows 계정)**: 그 분석의 어느 버전이라도 `JobInfo.Ip == 접속 IP` 또는 `JobInfo.Submitter == 이름`이면 내 것. 이름은 플러그인이 보낼 때 `Submitter`로 이미 보내므로, 웹은 접속 IP로 보낸 작업들의 `Submitter`를 모아 그 사람으로 본다. 한 IP에서 여러 이름이 보였으면 전부 내 것.
- 관리자 기능(B의 타입·투자비 편집, 서버 설정)은 기존 `Admin:Token` 로그인(`/admin/login`) 뒤에서만.
- 사내망: 페이지는 외부 자원(CDN·폰트)을 불러오지 않는다. 스크립트·CSS는 페이지 안.
- 기존 API(`/api/jobs`, `/api/analyses`, `/api/ash/*`)와 0.18~0.19 플러그인의 보내기는 계속 동작한다.
- 문구는 한국어, 표 수치에는 단위를 제목에("(대)", "(%)", "(초)").

## A. 웹 개편

### A.1 목표 / 비목표 / 실패로 볼 것

목표
- 홈에서 **내 분석의 진행 상황**(총 실행 예상 수, 완료 수, 단계, 완료 예상 시각)을 한눈에.
- 페이지 새로고침 없이 **내용만 갱신**.
- 분석 하나의 **결론을 한 화면**에: 숫자 3개 + 묶음별 그룹 막대 + 병목 지도 + 영향 큰 그룹 상위 N.
- 버전 **2~n개 나란히 비교**(기준 대비 증감).
- **영상**(만든 영상·진행 중 촬영·컷 편집기 진입)을 분석 화면 탭 하나로.

비목표
- 컷 편집기 자체 개편(진입만 쉽게).
- PPT 자동 생성, 로그인·권한, DXF를 웹 지도 배경으로.
- 플러그인 변경 없음.

실패로 볼 것
- 진행바가 100%를 넘거나 완료 뒤에도 "실행 중"으로 남는 것.
- 자동 갱신이 스크롤·선택 상태를 날리는 것.
- 그룹 20개 분석에서 결론 화면이 세로로 끝없이 길어지는 것.

### A.2 메뉴와 화면 구조

메뉴: **홈 · 분석 · 설정**. "작업" 메뉴는 없앤다. 기존 `/jobs`(대기열 전체)는 `/admin/jobs`로 옮겨 설정 안에서 "작업 대기열(관리자)"로 둔다. 기존 `/jobs/{id}`(버전 화면)는 주소와 내용을 유지한다.

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `/` | 지금 실행 중·대기 + 내 분석 목록(A.3). 기존 홈(배포·GitHub·서버 상태)은 `/admin/settings` 위쪽 "서버 현황" 절로 옮긴다 |
| 분석 목록 | `/analyses` | 홈과 같은 목록의 "전체" 보기. 검색(이름·보낸 사람) |
| 분석 | `/analyses/{id}` | 탭 4개: **현황 · 결론 · 비교 · 영상**(A.4~A.7). 탭은 `?tab=` |
| 버전(작업) | `/jobs/{id}` | 기존 그대로(결론·상세·입력·다운로드·로그). 상단 "분석 › 안 › v2" 헤더 유지 |
| 설정 | `/admin/settings` | 서버 현황 + 기존 설정 + B의 타입·투자비 링크 + 작업 대기열 링크 |

### A.3 홈

위에서 아래로.

1. **지금 실행 중** 카드(없으면 "실행 중인 작업 없음 · 작업 실행 켜짐/꺼짐"): `분석 › 안 vN`, 단계(`Phase`), 진행바, `실행 n / 예상 N회 · 1회 평균 m분 s초 · 완료 예상 HH:MM`, 실행 중 버전의 메모. 촬영(Film) 중이면 같은 카드에 "촬영 k/K".
2. **대기** 한 줄: 건수와 앞 2~3건의 `분석 › 안 vN (시작 예상 HH:MM)`.
3. 분할 토글 **내 것만 | 전체**(기본 내 것만. 내 것이 0건이면 전체로). 선택은 `localStorage`에 기억.
4. 분석 목록을 **진행 중**(실행·대기 버전이 하나라도 있음) / **완료**(전부 끝남) 두 절로 나눈다. 각 절은 마지막 보낸 시각 역순.
   - 한 줄: 분석 이름 · 상태 칩 · `안 a · 버전 v · 선정 s · 영상 f · 마지막 보냄` · 안별 최신 버전 칩(`A v2 24대`, 선정은 진한 칩, 실행 중은 진행률).
   - 분석 이름을 누르면 `/analyses/{id}`.
5. 접힘 **분석에 넣지 않은 작업 n건**(기존 `/analyses/unclassified` 링크).

### A.4 분석 — 현황 탭

- 상단: 이름·메모·만든 시각, 숫자 카드 `안 · 버전 · 선정 · 영상`.
- 실행·대기 중 버전 카드(홈의 실행 카드와 같은 모양). 실행 중이면 **중간 결과**: 지금까지 확정된 그룹 대수(`G01 4 · G02 3 · G03 6→5 시험 중`). 확정 전 그룹은 "탐색 중".
- 안별 절: 안 이름·메모, 버전 줄(`v2 [선정] · 24대 · 가동 78% · 결품 0초 · 날짜 · 보낸 사람 · 메모`). 줄 끝에 선정 토글과 "열기"(`/jobs/{id}`). 실패 버전은 빨간 칩과 오류 첫 줄.
- 안 추가·이름 바꾸기·옮기기·지우기는 기존 폼을 이 탭 아래 접힘으로.

### A.5 분석 — 결론 탭

- 보기 옵션 두 가지(라디오, 기본 **선정 버전 하나**; `localStorage`에 기억):
  - **선정 버전 하나**: 칩에서 버전을 고른다(기본: 가장 최근 선정, 없으면 가장 최근 완료). 아래가 그 버전의 결론.
  - **안별 펼침**: 안마다 그 안의 선정(없으면 최신 완료) 버전의 결론을 세로로 나열. 각 절은 아래와 같은 구성이되 지도는 작게.
- 결론 구성(한 화면, 2열 격자: 왼쪽 숫자·막대, 오른쪽 지도):
  1. 숫자 카드 3개: 권장 총 대수(시험 범위), 최대 가동률(상한·그룹), 최대 병목(block·평균 대기).
  2. **묶음별 그룹 막대**: `JobInfo.Clusters`로 묶어 묶음 제목 아래 그룹 가로막대(가동률, 상한선, 권장 대수 굵게). Clusters가 없는 옛 작업은 평평하게. 판정 실패 그룹은 빨간 막대와 이유.
  3. **병목 지도** 1개(평균 대기 기준; 점유율은 토글). 기존 `JobPages.Map` 재사용. 가장 심한 block 3개에 이름·값.
  4. **서로 영향이 큰 그룹 상위 3**: 영향표에서 |Δ가동률| 큰 순으로 문장 3줄. "영향표 전체"는 `/jobs/{id}?tab=detail`로.
  5. 버튼: 상세 보기(`/jobs/{id}?tab=detail`), Excel 보고서, 이 버전의 영상.
- 결론 탭은 기존 `JobView`를 그대로 쓴다(새 계산 없음).

### A.6 분석 — 비교 탭

- 버전 칩을 **2개 이상** 고른다(기본: 선정 버전 전부, 첫 번째가 기준). 칩 순서를 끌어서 바꾸지 않는다(기준은 "기준으로" 버튼).
- 표: 행 = 지표, 열 = 버전. 지표는 총 대수(대), 최대 가동률(%), 결품 합계(초), 교착(회), 최대 병목(block·초), 투자비(원, B가 있을 때만), 그룹별 권장(대), 그룹별 가동률(%). 기준 열 외에는 **기준 대비 증감**을 뒤에 작게(좋아진 쪽 초록, 나빠진 쪽 빨강: 대수·가동률·결품·교착·대기·투자비는 작을수록 좋음).
- 그래프: 그룹별 가동률 묶음 막대(SVG, 버전마다 한 색, 상한 점선). 3개 이상이면 열이 늘고 표·그래프는 `overflow-x:auto` 안에서 가로 스크롤.
- "병목 지도 나란히" 버튼: 고른 버전의 지도를 같은 축척으로 가로 배열.
- 기존 `AnalysisPages.Compare`(선정 버전 전부 × 그룹×4열)는 이 탭으로 흡수한다.

### A.7 분석 — 영상 탭

- 맨 위 버튼 **새 영상 만들기**(`/analyses/{id}/cuts`) · "컷 리스트 n개".
- 진행 중 촬영 카드(진행바 `컷 k / K`, 완료 예상, 취소).
- 완료 영상 카드: 요청 시각·조건(컷 × 버전, 해상도·fps), **썸네일**(ffmpeg로 첫 컷 1초 지점 1장, `thumb.jpg`, 없으면 회색 틀)과 재생(`<video>`), 컷별 목록, 전체 zip 받기(`/films/{id}/files/all.zip` 신설: 그 영상의 MP4 전부).
- 기존 `/films/{id}` 화면은 유지(카드의 "자세히").

### A.8 진행 예상과 자동 갱신

**예상 총 실행 수**는 서버가 입력(`ProjectInput`)과 작업 설정으로 계산한다(README의 탐색식).

```
묶음 b마다: 기준 1 + Σ_g ⌈log2(Max_g − Min_g + 1)⌉ + (패스 2개 가정) × k_b
+ 확정 반복 (Replications − InitialReps) + 확인 Replications
+ 영향표(Impact면) k 전체 × Replications
```

- 패스 수는 2로 가정하고, 실제 실행 수가 예상을 넘으면 예상을 `실제 + 남은 묶음 × k`로 올린다. 진행률은 `min(실행 수 / 예상, 0.99)`로 두고 `Done`일 때만 100%.
- 1회 평균 시간은 그 작업의 완료 실행 평균(없으면 최근 작업들의 `QueueInfo.Typical`). 완료 예상 = 지금 + (예상 − 실행 수) × 평균 ÷ `Jobs:Parallel`.
- `JobInfo`에 더하는 필드: `ExpectedRuns`(int?, 워커가 시작할 때 계산, 올릴 때 갱신), `Progress`(계산값, JSON에만).
- 중간 결과: 워커가 그룹 대수를 확정할 때마다 `JobInfo.Partial`(`Dictionary<string, int>`)과 `Phase`를 갱신한다(기존 `SearchJob`에 콜백 하나).

**자동 갱신**
- 새 JSON: `GET /api/home?me=1|0`(실행·대기·분석 목록), `GET /api/analyses/{id}/status`(현황 탭 데이터), 기존 `GET /api/jobs/{id}`에 `expectedRuns`·`progress`·`partial`·`eta`를 더한다. `GET /api/films/{id}`(촬영 진행).
- 페이지 스크립트: 실행·대기 중 항목이 하나라도 있으면 **10초마다** 해당 JSON을 읽어 `data-field` 요소의 텍스트·진행바 폭·상태 칩 class만 바꾼다. 없으면 폴링하지 않는다. 작업이 끝나면(Queued/Running → 끝) 페이지 위에 띠 "결과가 나왔습니다 — 새로 읽기"를 띄우고, 사용자가 누르거나 60초 뒤 한 번 다시 읽는다.
- `JobPages.Page`의 `<meta http-equiv="refresh">`는 없앤다(컷 편집기는 원래 없음).
- 폴링 중 네트워크 오류는 상단 작은 회색 글자 "연결 끊김 · 다시 시도 중"으로만.

### A.9 빌더에게 맡기는 것

- 페이지별 CSS·격자 치수(1280 기준 2열, 1024 이하 1열).
- JSON 모양. 서버 렌더 HTML + 작은 인라인 JS 구조는 유지(React 등 없음).
- 썸네일 ffmpeg 명령, 썸네일이 없을 때 틀.

## B. AGV 타입 카탈로그 · 투자비 (관리자)

### B.1 왜

타입 제원(속도·가감속·적재 시간)이 사람마다 달라 같은 차량이 분석마다 다른 값으로 돈다. 투자비는 결론에 함께 보여야 보고 때 쓸 수 있다. 서버에 **타입 카탈로그**를 두고, 플러그인의 Excel 양식이 그 값으로 채워지게 한다.

### B.2 데이터

**타입**(`types.json`, 서버 `Jobs:Dir\catalog\`)
| 필드 | 뜻 |
|---|---|
| `Name` | AutoMod 식별자 규칙(영문·숫자·_). Excel `AGV_Types.Type`과 같음 |
| `Label` | 표시 이름(한글 가능) |
| `Category` | `AGV` / `AMR` / `Conveyor`(컨베이어 상차형) / 기타 문자열 |
| `Kind` | 기존 `VehicleKinds`(Standard/Conveyor/Ant/Magnet). 모델 형상·적재 형태 검사용 |
| `Defaults` | 아래 기본값 묶음 |
| `Assets` | C의 에셋 ID 목록(없으면 빈 배열) |
| `Hidden` | 숨김(쓰는 안은 그대로 동작) |
| `UpdatedUtc`, `UpdatedBy` | 수정 기록. 버전 이력은 두지 않는다(서버 설계 5장의 불변 버전은 이번 범위 밖, 수정은 덮어쓰기 + 이전 파일 `.bak`) |

**기본값**(`Defaults`): 속도 4개 **`SpeedLoadedStraight`, `SpeedLoadedCurve`, `SpeedEmptyStraight`, `SpeedEmptyCurve`**(m/s), `Accel`, `Decel`, `Capacity`, `LoadTime`, `UnloadTime`, `MTBF`, `MTTR`, `Length`, `Width`, `Color`.

**투자비**(`prices.csv`, 같은 폴더): 열 `Type,UnitPrice,Currency,Note`. 관리자 화면에 **텍스트 영역으로 붙여넣기·수정**(CSV 그대로), 저장 때 검증(타입 존재, 숫자). 타입 화면에도 단가 칸이 있어 둘 중 어느 쪽에서 고쳐도 같은 파일.

### B.3 관리자 화면 `/admin/types`

- 표: 타입 이름·라벨·분류·형상·속도 4개·가감속·용기·상하차·길이·폭·색·단가·에셋 수·숨김. 행 클릭으로 편집 폼(같은 페이지 아래).
- 새 타입: 폼. 복제 버튼(기존 타입 값으로 시작).
- 투자비 절: CSV 텍스트 영역 + 저장. 저장 결과(바뀐 행 수, 오류 행 번호·이유).
- 에셋 절(C): 타입마다 에셋 목록·업로드·미리보기(C.3).
- 로그인은 기존 `/admin/login` 재사용.

### B.4 Excel 양식 연동 (Core + 플러그인)

- `AGV_Types` 시트 열을 바꾼다: `Type, Category, SpeedLoaded, SpeedLoadedCurve, SpeedEmpty, SpeedEmptyCurve, Accel, Decel, Capacity, LoadTime, UnloadTime, MTBF, MTTR, Length, Width, Color, Kind, Asset`.
  - `SpeedLoaded`·`SpeedEmpty`는 **직선 속도**(이름은 호환을 위해 유지). `*Curve`는 곡선 속도(빈칸·`-` = 직선과 같음). `Category`는 메모(모델에 영향 없음). `Asset`은 C의 에셋 이름(빈칸 = 타입 첫 에셋 또는 기존 `VehicleGeometry` 그림).
  - `ExcelReader`는 새 열이 없어도 읽는다(0.18 파일 호환). `ExcelTemplate`의 "양식 갱신(U)"이 빠진 열을 뒤에 더한다.
- `AGVEXCEL`(양식 생성·갱신)은 **서버가 있으면** `GET /api/catalog/types`를 읽어 `AGV_Types`를 카탈로그 타입 전부(숨김 제외)로 채운다. 서버가 없으면 지금처럼 `T_AGV` 한 행. 갱신(U)은 카탈로그에 있는데 파일에 없는 타입만 뒤에 더하고, 사용자가 고친 값은 건드리지 않는다. `Type` 드롭다운 목록은 카탈로그 이름.
- 곡선 속도의 모델 반영: **관문 B-G1**. AutoMod path mover가 호(arc) 구간 속도 제한을 `.asy`에서 지원하는지(세그먼트 속성 또는 `AGVVEHSEG`) 먼저 시험한다. 지원하면 `AsyWriter`가 호 구간에 적용(차량 타입별이 아니면 그룹 중 가장 낮은 곡선 속도), 아니면 `LogicGenerator`에서 호 구간 진입·이탈에 `set velocity`(구간 진입 이벤트가 로직에 없으면 **곡선 속도는 양식에 받되 "모델 미반영" 경고**로 둔다). 어느 쪽이든 결과 화면 입력 탭에 반영 여부를 표시.
- `InputSignature`에 곡선 속도를 넣는다(값이 반영될 때만).

### B.5 결론·비교에 투자비

- 버전 결론 숫자 카드에 **투자비**(Σ 그룹 권장 대수 × 타입 단가) 추가. 단가 없는 타입이 있으면 "단가 없음: T_X"로 표시하고 합계는 있는 것만.
- 비교 탭 지표에 투자비 행(A.6).
- 단가는 결론을 볼 때 현재 `prices.csv`로 계산(작업에 고정하지 않음. 단가가 바뀌면 옛 결론의 투자비도 바뀐다 — 보고서 작성 시점 값이 중요하면 PPT가 담당).

## C. 에셋 (3D → 경량 .cel, 미리보기)

### C.1 목표

타입마다 외형 에셋을 **여러 개** 둔다(컨베이어형은 주행 방향과 컨베이어 방향이 다른 경우가 있어 방향별로 따로). 3D 파일을 올리면 서버가 **경량 `.cel`**로 바꾸고 미리보기를 보여 준다. 플러그인이 내보낼 때 그 `.cel`을 모델 폴더에 넣는다.

### C.2 관문(먼저 시험, 결과에 따라 설계가 바뀜)

- **C-G1 `.cel` 형식**: 서버 설계 G3 그대로. 310(상자) 외에 원기둥 후보(320/321/350/351)와 그룹(700)·최상위(10000)의 필드 의미를 데모 `.cel`과 AutoMod 편집기 비교로 확정한다. 확정 전에는 **상자(310)만** 쓴다.
- **C-G2 3D 입력 형식**: STEP(`.stp/.step`)은 기하 커널이 필요해 서버에 오프라인 설치 가능한 라이브러리가 있어야 한다. 없으면 1차는 **STL/OBJ(삼각형 메시)**만 받는다(파싱이 단순). 어느 쪽이든 변환은 "부품(또는 연결된 메시 조각)마다 축 정렬 상자 1개"다.
- **C-G3 모델에 넣기**: 생성한 `.cel`을 차량 그래픽으로 연결해 AutoMod 모델이 빌드·실행되는지 이 PC에서 확인(`VehicleGeometry`가 지금 그림을 만드는 자리에 `.cel` 참조를 넣는 방식).

### C.3 기능

- 업로드: `/admin/types` 에셋 절에서 타입 고르고 파일 올림(STL/OBJ, 관문 뒤 STEP). 크기 제한(기본 50 MB).
- 변환 옵션: 최소 부품 크기(전체 길이의 % , 기본 2), 최대 상자 수(기본 200), 진행 방향(+X/+Y/−X/−Y), 원점(앞/중심/뒤), 90° 회전. **컨베이어 방향**(주행 방향 기준 0/90/180/270°)은 에셋의 메모 필드로 저장(모델에는 영향 없음, 사람이 고를 때 참고).
- 결과: `asset.cel` + 미리보기 PNG 3장(위·옆·사선, 서버가 상자 목록을 SVG→PNG 없이 **SVG로** 그려 페이지에 인라인. PNG 변환 라이브러리 없이).
- 에셋 = `{Id, TypeName, Name, Note, ConveyorDir, Boxes:n, Source:원본 파일명, CreatedUtc}`, 폴더 `catalog\assets\<id>\{source.*, asset.cel, preview.svg}`.
- 플러그인: `AGVEXCEL`이 `Asset` 드롭다운을 카탈로그에서 채우고, 내보내기(`LayoutExporter`) 때 `GET /api/catalog/assets/{id}/asset.cel`을 받아 모델 폴더에 복사하고 차량 그래픽으로 연결. 서버가 없거나 에셋이 없으면 지금 그림.
- 결과 화면 입력 탭에 쓴 에셋 이름.

### C.4 비목표

- 원기둥·회전체 재현(관문 C-G1 통과 전), 텍스처·색 세부, 에셋 버전 이력(덮어쓰기 + `.bak`).

### C.5 빌더에게 맡기는 것

- 메시 파서 선택(직접 구현 가능: STL ASCII/binary, OBJ v/f만).
- 연결 조각 분리 알고리즘(간단히: 파일에 부품 구분이 없으면 전체를 상자 1개 + 옵션으로 격자 분할).

## D. 자료 보관함 · 프로젝트/안건 입력

### D.1 목표

서버에 올라온 `input.xlsx`·DXF·DWG를 웹에서 **검색해 내려받아** 이어서 작업한다(작년 자료에서 자재 일부 수정, 범위 확장, 추가 안건). 프로젝트·안건을 넣는 방법을 정리한다.

### D.2 보관함 `/files`

- 데이터는 이미 있다: 각 작업의 `upload.zip`(`input.xlsx`, `<Model>.arc\*`, `drawing.dxf`, `input.cells.tsv`). **DWG는 지금 올라오지 않는다** → 플러그인 `AGVSEND`가 `layout.dwg`(현재 열린 도면 파일, 크기 제한 기본 100 MB)를 패키지에 더한다(`JobPackage.OptionalFiles`에 `drawing.dwg`). 0.19 이전 작업은 DXF까지만.
- 검색: 분석 이름·안·버전 메모·보낸 사람·모델명·날짜 범위·**자재 코드**(`input.cells.tsv`의 Materials 열에서 색인). 결과 줄: `분석 › 안 vN · 날짜 · 보낸 사람 · 모델 · 파일(xlsx / dxf / dwg 아이콘)`.
- 내려받기: 파일별(`/jobs/{id}/files/input.xlsx`, `drawing.dxf`, `drawing.dwg`) 또는 **이어서 작업 묶음**(`/jobs/{id}/files/continue.zip`: `input.xlsx` + `layout.dwg`(없으면 DXF) + `ash.settings.tsv` + `README.txt`에 "이 자료는 분석 X › 안 Y vN. ZWCAD에서 열고 AGVINIT 뒤 AGVSEND 때 같은 분석을 고르면 다음 버전, 새 안을 고르면 새 안").
- 분석 화면 현황 탭의 버전 줄에도 "자료 받기" 링크.
- 보관 기간: `Jobs:KeepRunsDays`는 실행 폴더만 지우므로 `upload.zip`은 남는다(현재 동작 유지). 관리자 분석 삭제는 기존대로.

### D.3 프로젝트명·안건 입력

- 구조는 컷 설계 4.1 그대로(분석 › 안 › 버전). 이름을 **처음 넣는 곳은 플러그인 `SendDialog`**(이미 있음). 웹의 "새 분석"·"안 추가"도 유지.
- 바꾸는 것:
  - 분석에 **분류 태그** 3개를 선택 입력: 법인·제품군·라인(서버 설계 6.4의 Corp/ProductLine/Line과 같은 이름). 자유 문자열, 자동완성(기존 값). 홈·분석 목록·보관함 검색에 필터로 쓴다.
  - `SendDialog`에 태그 3칸 추가(분석을 새로 만들 때만 활성). 서버 `POST /api/analyses`에 `corp, productLine, line` 선택 필드.
  - 분석 이름 규칙 안내문(화면 도움말): `<법인/동> <대상> <검토 목적>` 예 "P동 1층 AGV 대수 검토". 강제하지 않는다.
  - 안 이름 기본값: `A안`, `B안`… 자동 제안(다음 글자). 메모에 "무엇이 다른가" 적도록 자리 표시.
- 미분류 작업은 지금처럼 웹에서 옮긴다.

A·B·C·D는 파일이 거의 겹치지 않아 병렬로 간다. 겹치는 곳만 적는다.

릴리스: **A·D → 0.21.0**, **B·C → 0.22.0**(관문 결과를 반영한 뒤). 관문이 막힌 부분은 0.22.0에서 뺀다. 개발은 네 작업을 병렬로 하되 브랜치를 A·D / B·C로 나눈다.

내 결정
- 예상 실행 수 식은 `SearchJob`/`SearchStrategy`의 실제 로직에서 도출해 Core에 `SearchEstimate.Expected(ProjectInput, JobOptions)`로 둔다(README 식은 참고). 실제 > 예상이면 상향. ETA의 묶음 직렬 구간 오차는 허용한다.
