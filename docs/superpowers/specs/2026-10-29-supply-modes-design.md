# 공급 방식·위치 순환·공급 대기 통계 설계

2026-10-29. 사용자 요청과 대화로 정한 내용. "(우리 결정)"은 설계자가 정한 것으로 사용자가 검토할 항목이다.

## 왜

지금 ASH는 한 가지 공급만 흉내 낸다. 공정 재고가 호출 기준 이하가 되면 호출하고, 대기(standby) CP의 차량이 정해진 상차 CP 하나에서 실어 정해진 하차 CP 하나에 내린다. 현장에는 이것과 다른 두 형태가 있다.

- 호출 없이 차량이 상차와 하차를 계속 오가는 순환 공급. 대기 CP가 없다.
- 같은 자재를 여러 상차 위치에서 돌아가며 싣거나, 같은 자재를 따로 쓰는 여러 공정에 돌아가며 내리는 위치 순환.

또 차량이 짐을 실은 채 하차를 기다리는 동안(버퍼에서든 하차 CP에서든) 차량이 사실상 재고 버퍼 역할을 한다. 그 수량이 통계에 없어 공정 재고만 보면 결과가 이상해 보인다. 평균 재고 9.3 사례가 그랬다.

## 목표

1. 그룹마다 공급 방식을 고른다: 호출(지금 방식) / 순환.
2. 자재 행마다 상차 CP와 하차 CP를 하나 또는 여러 개 줄 수 있다. 여러 개면 순환한다.
3. 차량에 실린 채 하차를 기다리는 용기 수(공급 대기 수량)를 자재(공정)별로 세어 결과에 낸다. 두 공급 방식 모두 해당한다.

## 하지 않는 것

- 순환 그룹 하나가 여러 자재를 나르는 것. 순환 그룹에는 자재가 정확히 하나다. (사용자)
- 한 번 운행에 여러 하차 CP를 들르는 다중 정차(밀크런). 한 운행은 상차 하나, 하차 하나다.
- 가장 가까운 곳이나 가장 급한 곳을 고르는 동적 선택. 순환은 입력한 순서대로 돈다.
- 버퍼 CP, 회수 CP(rtnload / rtnunload)의 위치 순환. 이 칸들은 지금처럼 CP 하나다.

## 망치면 안 되는 것

- CP를 하나씩만 쓰는 호출 공급 자재의 결과가 바뀌면 안 된다. 0.36.0에서 넣은 "버퍼 없으면 하차 CP에서 언로딩 기준까지 대기"는 예외로 이미 바뀌었다.
- 쉼표나 범위가 없는 기존 엑셀은 그대로 읽혀야 한다.

## 입력

### AGV_Groups: 공급 방식 열

- 새 열 `SupplyMode`, 머리글 "공급 방식", 목록 `Call / Cycle`. 빈칸은 Call이다.
- Cycle 그룹이 지켜야 할 것(입력 검사):
  - 이 그룹을 쓰는 자재 행이 정확히 하나다. 아니면 오류.
  - StandbyCPs는 비워도 된다. 값이 있으면 쓰지 않는다고 경고한다.
  - FinishCP도 쓰지 않는다. 값이 있으면 경고한다.
  - 자재 행의 호출 기준은 쓰지 않는다. 경고하지 않는다. 필수 열이라 늘 값이 있다.
- Advanced(접힌) 열에 둘지 보이는 열에 둘지는 구현자 판단이다.

### Materials: CP 목록과 범위

- `SupplyFromCP`, `SupplyToCP` 칸에 아래를 쓸 수 있다. 상차만, 하차만, 둘 다 여러 개일 수 있다.
  - CP 하나: `L001`
  - 쉼표 목록: `L001,L003`
  - 범위: `L001-L010`
  - 섞기: `L001-L003,L007`
- 범위 규칙(우리 결정):
  - `-` 양쪽이 "같은 비어 있지 않은 접두어 + 숫자"일 때만 범위로 읽는다. 예: `L001-L010`.
  - 숫자 자릿수는 시작 쪽을 따른다. `L001-L010`은 L001 … L010이다.
  - 그 밖의 경우는 이름 하나로 읽는다. 예: `A1-B2`, `L001-1`. CP 이름에 `-`가 허용되므로 기존 이름이 그대로 읽혀야 한다.
  - 범위 모양인데 시작이 끝보다 크면 오류다.
  - 같은 CP가 두 번 나오면 한 번만 쓰고 경고한다.
- 각 CP는 지금 검사 규칙을 그대로 받는다. 도면에 있어야 하고, 상차 칸은 load, 하차 칸은 unload TYPE이다. 범위 안의 CP가 하나라도 도면에 없으면 오류다.
- 엑셀 데이터 유효성(목록)이 이 칸에 걸려 있으면 쉼표나 범위 입력이 막힌다. 구현자가 확인하고, 막히면 그 칸의 목록 검사를 경고 수준으로 낮추거나 없앤다.

## 동작

### 하차 CP가 여러 개 = 공정이 여러 개

- 하차 CP마다 따로 소비하는 공정이다. (사용자) 각 공정이 자기 재고, 소비, 호출, 품절, 통계를 가진다.
- 모델 안에서는 자재 행 하나를 하차 CP 수만큼의 "공정 자재"로 펼친다.
  - 이름: `M001@U002` (우리 결정)
  - 하차 CP가 하나면 펼치지 않고 이름도 그대로 `M001`이다. 기존 결과와 같게 하기 위해서다.
  - 펼친 공정 자재들의 값은 원래 행의 것을 똑같이 쓴다: 택트, 원수, 용기당 수량, 호출·언로딩 기준, 안전재고, 초기 재고, 형태, 버퍼, 회수.
  - 초기 재고 방식(Uniform / Staggered)은 펼친 뒤의 순서로 적용한다. (우리 결정)
  - 엑셀 표시(오류·경고 위치)는 모두 원래 행을 가리킨다.
- 결과 표, 보고서, 원인 분석에는 공정 자재가 한 줄씩 나온다.

### 상차 CP가 여러 개

- 운행 하나를 시작할 때 다음 상차 CP를 고른다. 순서는 입력 순서대로 돌고 끝나면 처음으로 간다.
- 차례는 자재(행) 하나에 하나를 둔다. 여러 차량이 같은 차례를 이어 쓴다. (우리 결정)
- 호출 공급과 순환 공급 모두 같다.

### 호출 공급

- 지금과 같다. 공정마다 따로 호출하고, 차량은 호출한 공정의 하차 CP로 간다. (사용자) 하차 위치를 순환하지 않는다.
- 언로딩 기준 대기는 0.36.0 규칙 그대로다. 버퍼가 있으면 버퍼에서, 없으면 하차 CP에서 기다린다.

### 순환 공급

- 차량은 대기 CP 없이 계속 돈다. (사용자)
  1. 다음 상차 CP로 간다.
  2. LoadTime 동안 Capacity만큼 싣는다.
  3. (버퍼가 있으면) 버퍼로 가서 대기한다.
  4. 다음 하차 공정의 하차 CP로 간다.
  5. 그 공정 재고가 언로딩 기준 이하가 될 때까지 기다린다.
  6. UnloadTime 뒤 재고가 늘어난다.
  7. (회수가 있으면) 회수 구간을 지난다.
  8. 다시 1로 간다.
- 하차 공정이 여러 개면 운행마다 다음 공정으로 넘어간다. (사용자) 차례는 상차와 같은 방식으로 자재 하나에 하나다.
  - 앞 공정 재고가 내려가지 않으면 그 차량은 그 공정에서 계속 기다린다. 사용자가 정한 순환 규칙의 결과이고, 공급 대기 통계로 드러난다.
- 호출과 V_pending은 쓰지 않는다. 소비 루프는 재고를 줄이고 품절과 통계만 기록한다.
- 순환 차량은 쉬지 않는다. 상차 CP에 도착하면 바로 싣고 하차로 떠난다. 상차 CP를 막고 서 있는 차량은 없다. (사용자)
- 시작 위치와 대수 시험(우리 결정):
  - 순환 그룹은 시험하는 대수만큼만 차량을 넣어 모델을 빌드한다. 쓰지 않는 차량이 경로를 막지 않게 하기 위해서다.
  - 같은 대수의 모델은 저장해 두고 다시 쓴다. 대수 하나당 빌드가 한 번 더 든다.
  - 활성 차량은 상차→하차 경로 위에 간격을 두고 자동으로 만든 시작 CP에서 출발한다. 도면에 그릴 것은 없다.
  - StandbyCPs와 FinishCP는 쓰지 않는다. 값이 있으면 경고한다.

### 순환 그룹의 권장 대수

- 기준은 품절·가동률이 아니다. 앞 차량이 하차를 마치고 떠날 때 뒤 차량이 이미 와서 기다리고 있으면 된다. 즉 차량 교체 시간이 최소가 되는 가장 적은 대수다. (사용자)
- 교체 시간: 하차 CP마다, 앞 차량이 떠난 시각부터 다음 차량이 하차를 시작할 수 있는 시각(도착 또는 줄에서 당겨 섬)까지의 시간.
- 뒤차 대기율: 떠날 때 뒤 차량이 이미 대기 중이던 비율.
- 권장 대수(우리 결정): 뒤차 대기율이 95% 이상인 가장 적은 대수다.
  - 한 대를 더해도 평균 교체 시간이 거의 줄지 않으면(당겨 서는 시간 수준) 거기서 멈춘다.
  - 탐색 범위는 그룹의 MinCount~MaxCount다.
  - 95%는 Settings에 값으로 둘지 구현자가 정한다. 기본값은 95다.
- 결과 화면과 보고서에는 대수별 교체 시간 평균·최대, 뒤차 대기율, 공급 대기 수량을 함께 보여 준다.
- 가동 시간:
  - 운행 시작부터 다음 운행 시작까지가 가동이다.
  - 언로딩 기준 대기 중 BufferWaitSec을 넘는 부분은 비가동이다. 호출 공급과 같은 규칙이다.
  - 그룹 시간 분해(tsplit)도 운행 단위로 같은 항목을 채운다.
- 리드타임 항목(호출→상차, 호출→하차)은 순환 그룹에서는 운행 시작 기준으로 재거나 비운다. 구현자가 정하고 결과 화면에 "순환"이라고 표시한다.

### 공급 대기 수량 통계

- 정의: 언로딩 기준 때문에 실린 채 기다리는 용기 수. 공정 자재별로 센다.
  - 버퍼에서 기다리는 차량과 하차 CP에서 기다리는 차량 모두 포함한다.
  - 주행 중인 짐은 넣지 않는다. 주행 중인 양은 지금의 V_pending 쪽 개념이다.
- 기다리기 시작할 때 늘리고, 끝날 때 줄인다(`V_waitQty(m)`). 대기 차량 수(`V_waitVeh(m)`)도 함께 센다.
- 재고와 같은 시점(소비 루프의 택트마다, 워밍업 뒤)에 표본을 잡아 평균·최대를 낸다. 재고와 같은 방식이라 비교할 수 있다.
- 결과에 나오는 곳:
  - result.tsv의 자재 행
  - ResultSet / JobView
  - 작업 화면 자재 표: "공급 대기(용기) 평균/최대", "대기 차량 평균"
  - 결론 탭의 자재 재고 줄
  - 보고서 자재 시트
- 재고 + 공급 대기를 함께 보여 "라인 쪽에 실제로 묶인 양"이 보이게 한다. 열을 하나 더 둘지, 툴팁으로 보여 줄지는 구현자 판단이다.

## 영향 범위 (구현자가 확인할 곳)

- 입력: ExcelTemplate(새 열·라벨·유효성), ExcelReader(목록 파싱, 펼치기), InputValidator(Cycle 규칙, CP 목록 검사), InputSignature.
- 모델: LogicGenerator, 템플릿 code_material / code_group.
  - 순환용 공급 프로시저를 새로 만들지, 기존 P_supply를 분기할지는 구현자 판단이다.
  - 상차 CP 선택은 차례 변수와 if 사슬 정도면 된다.
- 결과: result.tsv 쓰기·읽기, ResultSet, JobView, JobPages, JobReport, StockoutCauses.
  - 순환 그룹의 품절은 "배차 대기" 판정이 맞지 않는다. 판정 기준(우리 결정):
    - 자유 순환 시간: 상차 + 하차 + 정해진 시간 + 도면 최단 주행. 하차 공정이 여러 개면 공정마다 계산한다.
    - 구조적: MaxCount 대가 자유 순환 시간으로 돌아도 공급 속도(용기/시간)가 공정들의 소비 속도 합보다 작다.
    - 대수 부족: MaxCount로는 따라가지만 활성 대수의 자유 순환으로는 못 따라간다.
    - 교통·교착: 대수로는 따라가는데 실제 운행 시간이 자유 순환 시간보다 크게 길다. 기존 교통 판정과 같은 문턱을 쓴다.
    - 공정 차례 대기: 공급 대기가 길어 다른 공정이 굶는 경우. 공급 대기 통계와 함께 "순환 차례 대기"로 보여 준다.
    - 제안 문구는 호출 기준 대신 대수나 언로딩 기준을 말한다.
- SupplyFromCP / SupplyToCP를 읽는 다른 곳: RouteView, DetourCauses, RouteGroupCheck, GroupClusters, ExcelDrawingDiff, ExcelMarks, FilmWorker, 플러그인 루트 보기, AGVSUPPLY 표.
  - 목록이면 모든 CP를 다루거나 첫 CP를 대표로 쓴다. 곳마다 구현자 판단이다.
  - 플러그인 루트 보기는 모든 상차·하차 CP를 그린다.
- 문서: docs/input-template.md, docs/manual(입력·결과), 릴리스 노트.

## 구현자에게 맡기는 것

- 순환 프로시저 구조, 변수 이름, 표본 방식의 세부.
- 공급 방식 열의 위치(보이는 열 / 접힌 열).
- 리드타임 항목을 순환 그룹에서 어떻게 보일지.
- 목록 CP를 쓰는 분석 코드마다 "전부" 또는 "첫 CP" 선택.

## 확인 방법

- 단위 테스트:
  - 범위 파서
  - 펼치기(이름, 값 복사, 엑셀 행)
  - Cycle 검사 규칙
  - 생성 로직 문자열(순환 루프, 상차 차례, 공정 차례, 대기 수량 증감)
  - 결과 읽기
- AutoMod 통합 테스트(로컬 `C:\AutoMod\12_6`, `ASH_AM_HOME`):
  - 순환 그룹 1개, 하차 공정 2개 모델 빌드·실행 → 품절과 공급 대기 수량이 상식적인 범위인지
  - 호출 공급, 상차 2곳 모델 빌드·실행
- 기존 단일 CP 호출 공급 테스트의 생성 로직이 바뀌지 않아야 한다.
