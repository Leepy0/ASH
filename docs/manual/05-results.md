## 5.1 홈

| 번호 | 구획 | 내용 |
|---|---|---|
| ① | 진행 | 실행 중·대기 중인 작업과 영상. 진행률, 끝날 시각 |

## 5.2 분석 — 결론

분석 화면 위쪽 탭: **결론 · 비교 · 원인 · 영상 · 버전**. 오른쪽 위 버튼: 영상 보기 · 영상 만들기 · 보고서 받기.

![결론](img/web-conclusion.png)

| 번호 | 무엇 | 읽는 법 |
|---|---|---|
| ① | 핵심 숫자 | 권장 대수(다른 안과의 차이), 최대 가동률, 자재 품절. 단가가 있으면 투자비 |
| ② | 그룹별 권장 대수 | 그룹마다 대수와 가동률 막대. 문제 있는 그룹이 먼저 |
| ③ | 범례 | 주황 = 경고: 상한 초과, 파랑 = 적정, 회색 = 10 % 미만 |
| ④ | 안별 결론 | 안마다 선정(또는 최신) 버전의 대수·가동률·자재 품절. 누르면 그 버전 결론 |
| ⑤ | 생산량 한계 (T/T) | 접힌 칸. [5.5](#55-생산량-한계-tt) |
| ⑥ | 병목 지도 | 평균 대기 · 점유율 · 통행량. block을 색으로, 상위 5개를 번호로. "＋ 컷"으로 그 block을 찍는 영상 컷 |
| ⑦ | 상세 | 이 버전의 작업 화면([5.7](#57-작업-화면)) |

버전 선택 상자(⑦ 왼쪽)로 다른 버전의 결론을 본다.

순환(Cycle) 그룹은 가동률 대신 뒤차 대기율로 판정한다.

| 칸 | 순환 그룹 |
|---|---|
| ② 그룹 줄 | `뒤차 대기 96% · 교체 평균 12초 · 교체 최대 40초`. 마우스를 올리면 "권장 사유 뒤차 대기 ≥ 95%" |
| 권장 대수 | 뒤차 대기율이 기준(Settings `CycleFollowRate`, 기본 0.95) 이상인 가장 적은 대수 |
| 실패 | `뒤차 대기 80% < 95%` |
| 자재 재고 줄 | ` · 공급 대기 평균 1.5` |

- 교체 시간: 앞 차량이 하차 공정을 떠난 때부터 뒤 차량이 대기 위치(버퍼, 없으면 하차 CP)에 도착할 때까지. 이미 와 있으면 0초.
- 뒤차 대기: 교체 시간이 당겨 서는 시간(차량 길이 + 0.5 m, 가감속 포함) + 5초 이하.
- 뒤차 대기율 = 뒤차 대기 교체 ÷ 전체 교체.

확인 실행에서 교착이 났으면 **교착** 칸, 자재 품절(라인이 자재가 없어 선 시간)이 있으면 **자재 품절 원인** 칸이 그룹별 권장 대수 아래에 나온다. 작업 화면([5.7](#57-작업-화면))에도 같은 칸이 있다. 읽는 법은 [5.3 자재 품절 원인](#자재-품절-원인).

| 통행량 보기 |
|---|
| ![통행량](img/web-conclusion-traffic.png) |

*경로마다 지나간 차량 수(확인 실행 평균). 가장 붐비는 경로 5개를 번호로 짚는다. 예제에서는 P002·P003 79대, P004 78.5대, P007 60대, P001 22.5대 순.*

## 5.3 원인

![원인](img/web-cause.png)

| 번호 | 무엇 |
|---|---|
| ① | 버전과 실행(시드) 고르기. 기본은 문제가 가장 큰 실행 |
| ② | 원인 항목. 정도(참고·주의·심각), 제목, 위치, 상세, **조치**. 줄을 누르면 펼쳐져 관련 경로·CP·block 그림이 나온다 |
| ③ | 작업당 시간: 한 작업이 주행 · block 대기 · CP 대기 · 상하차 · 기타에 몇 초 썼는지 |

오른쪽 지도의 번호가 항목 번호다. 시각이 있는 항목에는 "영상 컷" 버튼이 있다(그 장면 컷을 만들고 영상 만들기를 연다).

| 원인 종류 | 뜻 |
|---|---|
| 간격 부족 | 경로가 벽·기둥·설비에 차량 폭/2 + 안전 거리보다 가깝다 |
| block 점유 | block을 너무 일찍 잡거나 늦게 놓는다(예: 정차 CP가 block 출구 바로 뒤) |
| 교착 · 교착 위험 | 서로 기다리는 block 고리 |
| 자재 품절 | 라인이 자재가 없어 선 자재. 구조적 · 배차 대기 · 교통·교착 · 변동으로 가름(아래) |
| 우회 | 루트가 직선거리보다 훨씬 길다(끊긴 연결, 틀린 방향) |
| 주행 부하 | 수요 비율보다 주행을 훨씬 많이 차지하는 자재 |
| 시간 손실 | 대기가 순수 주행의 1.5배 이상인 그룹 |

### 자재 품절 원인

가동률은 낮은데 자재 품절이 나는 이유를 자재마다 가른다. 원인 탭의 "자재 품절" 항목, 결론 탭·작업 화면의 "자재 품절 원인" 칸, 보고서의 "자재 품절 원인" 시트가 같은 계산이다. 칸의 리드타임·판정·처방은 품절이 가장 긴 실행 기준이고, "지도"는 그 실행의 원인 탭을 연다.

| 숫자 | 계산 |
|---|---|
| 용기 1개 소비 | TaktTime × UnitsPerContainer ÷ UnitsPerCycle (컨베이어 소비 자재는 제품 투입 간격) |
| 호출 시 남은 시간 | CallThreshold × 용기 1개 소비. 호출이 나갈 때 남은 재고로 라인이 버티는 시간 |
| 최소 리드타임 | 대기 CP→상차 CP 공차 주행(SpeedEmpty) + LoadTime + 적재 주행(상차→[버퍼]→하차, SpeedLoaded) + ExtraTime + UnloadTime. 도면 최단 경로, 대기·정체 없음. 대기 CP가 없으면 공차 주행 0 |
| 리드타임 평균/최대 | 호출→하차 완료(실행 결과) |
| 배차 대기 | 호출→상차 CP 도착 평균 − 공차 주행. 빈 차를 기다린 시간 |
| 이동 초과 | (호출→하차 평균 − 호출→상차 평균) − 상차부터 하차까지의 최소 시간. 적재 구간의 정지·서행 |
| 이동 중 정지 | 그룹 작업 시간 중 정지 비율 |

판정은 위에서부터 먼저 맞는 것 하나:

| 판정 | 조건 | 처방 |
|---|---|---|
| 구조적 | 최소 리드타임 ≥ 호출 시 남은 시간. 대수를 늘려도 못 고친다 | CallThreshold를 ⌈최소 리드타임 ÷ 용기 1개 소비⌉ + 1로 |
| 배차 대기 | 배차 대기 ≥ 30초이면서 공차 주행 이상(상차 도착이 공차 주행의 2배 이상), 이동 초과보다 큼 | 차량 유휴 30 % 이상이면 대기 위치·배차 규칙(Nearest/FIFO) 점검, 아니면 대수 +1 (호출 몰림) |
| 교통·교착 | 이동 초과 ≥ 30초이면서 적재 구간 최소 시간의 절반 이상(적재 구간 1.5배 이상), 또는 그 그룹 차량·경로 block의 교착 | 경로가 지나는 block 중 작업당 대기(점유 횟수 ÷ 작업 수 × 평균 대기)가 큰 것 |
| 변동 | 리드타임 평균 < 호출 시 남은 시간 ≤ 최대. 몰릴 때만 늦음 | CallThreshold 또는 안전재고를 ⌈(최대 − 남은 시간) ÷ 용기 1개 소비⌉만큼 올림 |
| 여유 부족 | 평균도 늦지만 배차 대기·이동 초과 어느 쪽도 크지 않음 | CallThreshold를 ⌈최대 ÷ 용기 1개 소비⌉ + 1로 |
| 기타 · 자료 부족 | 리드타임이 남은 시간 안인데 품절(초기 재고 등) · 이전 모델이라 결과 행 없음 | 이벤트 기록 확인 · 상세에 빠진 자료(matstat, tsplit, 차량 시간) 표시 |

순환(Cycle) 그룹의 공정은 호출이 없어 판정이 다르다(위에서부터 먼저 맞는 것 하나):

| 숫자 | 계산 |
|---|---|
| 자유 바퀴 | LoadTime + UnloadTime + ExtraTime + 상차→[버퍼]→이 하차 CP[→회수] 적재 주행 + 상차 CP로 돌아가는 공차 주행. 도면 최단 경로 |
| 실제 바퀴 | 활성 차량의 (가동 구간 ÷ 운행 수) 평균 |
| 공급·소비 | 대수 × Capacity ÷ 자유 바퀴 · 같은 그룹 공정들의 소비 합(용기/시간) |
| 공급 대기 | 이 공정에서 차량에 실려 기다린 용기 평균 |

| 판정 | 조건 | 처방 |
|---|---|---|
| 구조적 | MaxCount 대가 자유 바퀴로 돌아도 공급 < 소비 | 순환 경로 단축 또는 그룹 분리 |
| 대수 부족 | MaxCount로는 따라가지만 활성 대수로는 공급 < 소비 | 그룹 대수 ⌈소비 × 자유 바퀴 ÷ Capacity⌉대 이상 |
| 교통·교착 | 실제 바퀴가 자유 바퀴의 1.5배 이상이고 30초 이상 김, 또는 교착 | 경로가 지나는 block 중 작업당 대기가 큰 것 |
| 순환 차례 대기 | 같은 자재 행의 다른 공정에서 차량이 공급 대기(평균 1용기 이상) | 그 공정 UnloadThreshold 낮춤 · 공정 분리 |
| 기타 · 자료 부족 | 위에 안 맞음 · 결과 행 없음 | 이벤트 기록 확인 · 초기 재고 |

정도는 품절 시간: 10분 이상 심각, 1분 이상 주의. 데이터로 알 수 없는 것: 품절 순간의 차량 위치·호출 몰림의 시각(평균·최대만 있음), 대기 CP가 여러 개일 때 실제로 출발한 곳(가장 가까운 곳으로 계산), 여러 자재가 같은 그룹을 나눠 쓸 때 자재별 정지 비율(그룹 전체 값).

같은 분석을 도면에 그리려면 ZWCAD 팔레트 원인 탭 "원인 보기"(`AGVCAUSE`, [3.8](03-drawing.md#38-원인-표시-agvcause)).

## 5.5 생산량 한계 (T/T)

결론이 나온 버전의 권장 대수 그대로, 모든 자재의 T/T를 줄여(생산량 +10 %, +20 % … +50 %) 다시 돌린다. 어디까지 버티는지 본다. 결론 탭 "생산량 한계 (T/T)"를 펼치고 "다시 계산"(보낸 PC와 관리자만).

![생산량 한계](img/web-limit.png)

*예제: +0 %(T/T 40~60초)부터 +50 %(26.7~40초)까지 모두 통과. 막대 길이 = 생산량.*

## 5.7 작업 화면

결론의 "상세" 또는 버전 탭 "열기". 탭: **결론 · 상세 · 입력·추적 · 다운로드·로그**.

![작업 화면 결론](img/web-job-summary.png)

| 번호 | 무엇 |
|---|---|
| ① | 탭 |
| ② | 권장 AGV 총 대수(시험 범위), 최대 가동률, 자재 품절 시간, 투자비 |
| ③ | 판정. ✓ 확인 실행 통과 / 경고 / 실패, 모델 실행 횟수 |
| ④ | 시간 내역 막대: 적재 주행 · 공차 주행 · 상하차 · 버퍼 대기(허용) · 고장 · 버퍼 대기(허용 초과) · 유휴. 앞의 다섯 개 합 = 가동률 |
| ⑤ | 대수 바꿔 다시 돌리기: 그룹 대수를 −/+로 바꾸고 "확인 실행 보내기". 같은 안의 새 버전이 된다(보낸 PC와 관리자만) |
| ⑥ | 자재별 리드타임·재고: 공급/기대 횟수, 자재 품절 시간, 호출→상차·하차 시간, 재고 평균·최소·최대, 공급 대기 평균·최대(용기), 대기 차량, 재고+대기 평균 |
| ⑦ | 병목: block 점유율·평균 대기 지도와 "대기가 긴 block" 표 |
| ⑧ | Excel 보고서 받기 |

- 하차 CP가 여러 개인 자재: 공정마다 한 줄(`M001@U001`, `M001@U002`).
- 공급 대기: 언로딩 임계 때문에 차량에 실려 기다리는 용기(버퍼·하차 CP). 주행 중인 짐은 제외. 재고와 같이 택트마다 잰 값.
- 재고+대기: 라인 쪽에 실제로 묶인 양.

위쪽 줄: 다른 분석·안으로 "옮기기", 안의 대표 버전으로 "선정", "이 버전으로 영상 만들기".
